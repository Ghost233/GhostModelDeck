# 实例配置独立于模型资产和运行进程

2026-10-12，用户确认将模型、引擎和启动参数保存为独立实例配置。同一模型与引擎可保存多份参数不同的实例，委员会成员引用保存的实例。这样可以分别管理同一模型的不同用途，避免参数继续附着在模型资产上。

保存的实例配置与实际运行进程分别表达。实例、模型或引擎缺失时，保留配置并标红；恢复资源后可以继续使用。该决定调整 ADR 0003 的模型启动覆盖组织方式，并将 ADR 0002 的委员会成员引用从模型与引擎组合转向实例配置。参数解析、文本优先、真实调用和生命周期的其他约定继续保留。

第一轮讨论中，用户确认公开 HTTP 按实例选择；每份配置最多一个运行中的实例，重复启动复用已有作业或实例。下载保存目录在选择时自动加入模型库，但可解除读取关联，下载位置和文件保持。目录离线或解除关联等引用失效也标红；单纯未运行显示“已保存”。

保存只影响后续启动，已有进程保留原参数，不自动重启。委员会的原有 partial 规则继续保留。

第二轮中，用户确认显示名称与公开调用名分开。普通改名不改变公开名；实例和委员会共享唯一公开名称空间。创建委员会重名时先报错，再给出可用名称建议，不能自动改名保存。

用户明确不做旧配置迁移或向后兼容，采用新结构直接覆盖，取代本次讨论中曾建议的自动迁移。模型库按真实路径去重，不同位置的副本分别管理。解除目录关联或磁盘离线不主动停止已有进程；引用失效标红，禁止新启动或重启，仍可停止已有实例。失效实例可重新绑定资源，保留实例身份与引用，变更只影响后续启动。

第三轮中，用户确认应用配置按新结构重新建立，保留磁盘模型、引擎文件和历史结果文件。普通启动只核对健康、加载与身份，生成和概率测试由用户主动触发。实例保存完整参数快照；引擎默认值变化不改变已保存实例。

切换引擎不自动转换 CLI，编辑期间分别暂存草稿，保存当前组合。原位置更新在下一次启动生效，不自动重启现有进程。删除实例配置须先停止运行，保留模型和引擎文件，委员会引用失效标红。明确修改公开调用名后，旧名失效，不保留别名。

第四轮中，用户确认能识别模型格式和基本信息时允许关联及创建实例，不按管理器预设架构或模型名称名单过滤。实际兼容性由引擎与用户实测判断，真实损坏或缺失仍提示。

已关联目录内的模型链接按真实目标路径读取和去重，不扩展扫描目标目录的其他文件。删除这种项只移除库内链接，保留外部实际权重，运行中的模型删除保护保持。
