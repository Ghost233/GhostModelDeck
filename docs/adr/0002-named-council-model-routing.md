# 按模型标识选择命名委员会或原生 JEV

用户希望以 quick、hard 等委员会模型标识选择独立配置，并以原生 JEV 模型名直接调用单模型。为使客户端能够直接选择决策来源，选择把原先固定 gmd-council 与全局席位选择扩展为显式命名路由：委员会模型关联委员会配置，原生模型路由跳过委员会聚合并复用既有受管调用边界。

Q15–Q18 已确认：每份配置允许选择席位、绑定模型和设置超时，保留统一的等权综合与至少一席完整成功规则；配置在软件内管理并持久保存；原生直连限本机已登记且 Ready 的 JEV；两类模型共用唯一调用名称，重名拒绝，不采用隐式优先级或强制前缀。

Q19–Q23 已确认：原生模型使用用户设置的固定调用名，响应 model 使用该名称；HTTP/MCP 必须显式指定 model，不保留特殊默认 gmd-council。席位保存模型资产与引擎绑定，运行时解析 Ready 实例，不可用或歧义席位失败，其他完整成功席位仍可返回。运行中的请求使用入场快照，配置修改、重命名和删除只影响后续请求。软件展示配置与可用状态，HTTP/MCP 发现当前可调用模型并区分来源。

Q24–Q25 已确认：MCP 决策工具替换为 decide_jev / decide_jev_batch 并要求 model，同步工具发现及连接配置；允许先保存未就绪模型的调用名与席位，配置不触发模型加载，推理仍检查 Ready 与题型能力。

这些决定用显式命名路由替代固定默认委员会，避免模型重启、配置切换及不明确的默认选择改变客户端实际请求的来源；请求快照同时保持每次输出与配置可对账。用户已确认完整需求，本记录取代 ADR 0001 的固定模型标识决定与旧 MCP 工具命名，其余委员会 JEV 输出及聚合语义沿用 ADR 0001；原生直连保留校验后的实际判断与用量，不套用委员会重算规则。当前状态为已确认、待实施，不表示功能已经实现。完整需求见 [补充需求](../requirements/jev-model-routing-and-council-profiles.md)。
