# 虚拟 JEV 引擎的公开结果与调试结果分离

规范规格：[命名 JEV 模型路由、标准协议与应用内推理测试场规格](https://github.com/Ghost233/GhostModelDeck/issues/32)。

2026-10-07，用户选择把委员会作为虚拟 JEV 引擎，通过应用自有协议转换器提供 Jev typed HTTP 与 MCP 结果，以便客户端消费 JEV 兼容结构。相比默认公开完整委员会自有结构，默认结果使用 JEV 兼容表达，软件、HTTP、MCP 只有单次明确开启 debug 时才额外提供每席依据和完整委员会总结果。OpenAI Chat 输出转换因结构复杂推迟讨论；完整需求已由用户确认，待实施，本记录不表示功能已经实现。

项目尚未上线，用户选择直接修改现有 MCP 工具契约，避免维护平行的旧协议工具。成功条件沿用有效结果优先：至少一席成功即可返回，单席时使用该席结果，多席时综合有效席位，只有零席成功才失败；默认结果不附完整委员会结构，覆盖及失败细节通过 debug 查看。

为保持标准 JEV 字段兼容，用户确认对 choice/score 综合分布应用原生 confidence 算法，noul 保持原生 scalar 结构。该字段表达概率分布形状，不表示真实正确率或席位一致性。

最初约定虚拟引擎使用固定公开模型 ID `gmd-council`，以便席位变化时客户端仍调用同一委员会；该身份决定现由 [ADR 0002](0002-named-council-model-routing.md) 的显式命名路由替换。委员会用量统计参与结果的成功席位实际输入 token，不估算失败席位的未知用量；委员会最高概率完全相等时按候选 ID 排序选择单值结果，详细来源与并列信息放入 debug。

批量结果按整席校验，不按题拼接局部成功。超时可使用已完成有效席位，主动取消则撤回本次成功输出，已有证据只用于 debug，晚到结果不得改变已结束请求。测试场的 HTTP/MCP 模式通过实际本机入口验证客户端调用链路，原生模式复用同一受管 Ready 实例。

用户后续将本期测试场与专项验收限定为 JEV，标准文本 llama.cpp/oMLX 和 SSE 验收移出本期。范围按 JEV 决策能力定义，承载该能力所需的现有兼容后端调用与资源控制仍属于 JEV 链路。

后续多份命名委员会配置与原生模型直连需求已由用户整体确认，见 [ADR 0002](0002-named-council-model-routing.md)。该决定替换固定默认 gmd-council 与旧 MCP 工具命名，其余标准输出、综合、取消和 debug 边界沿用本记录；原生直连保留引擎实际决策，不套用委员会综合规则。
