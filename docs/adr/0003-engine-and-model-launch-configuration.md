# 引擎默认启动配置与模型启动覆盖

2026-10-08，用户确认启动参数按「引擎保存默认配置，每个模型可覆盖」组织，并要求每个引擎支持自定义填写、尽可能解析，至少能识别软件内置识别的引擎参数。引擎之间的命令格式不同，同一引擎运行不同模型时的上下文和资源需求也不同，单套全局参数或仅有引擎默认值不足以表达这些差异。

用户随后确认常用参数表单与高级文本并存，模型路径/监听/对外标识由软件管理；未知参数保留并提示。用户进一步选择文本优先：表单仍可填写，同名选项以文本值为准，表单标红提示覆盖关系，语义错误也只提示，由引擎报告真实启动结果。原始文本不因解析或提示被自动改写。

用户进一步明确文本优先，解析尽力提示、不强求识别；粘贴中的软件管理字段识别后剔除并说明实际采用值。模型覆盖按模型变体与具体引擎登记项分别保存，避免不同量化或引擎的参数互相污染。

模型覆盖保存整段独立参数配置，并提供最终输出参数预览。这使模型配置独立于后续引擎默认值变化，同时避免依靠不完整解析对未知参数做差异合并。模型恢复继承时保留独立配置供再次切换；独立空配置与未覆盖分别表达。

用户确认完整命令预览与实际启动命令记录，文本仅填写参数，可执行文件及子命令由软件生成。保存仅影响后续启动，已有运行实例保留原参数，用户手动重启时应用新参数。

可运行引擎的初始表单沿用当前软件默认参数，文本初始为空。无法拆分为参数列表的文本允许保存，但启动前要求修正；已能拆分的参数仍按语义仅提示规则处理。

引擎管理页编辑默认配置，运行模型时编辑模型独立配置，两处使用同样的表单、文本与预览编辑器。识别结合内置规则与当前版本的帮助信息，尽力补充名称、别名和说明，未知内容继续保留。

引擎升级保留原配置并刷新识别，解除关联保留配置供用户手动恢复。本次将参数应用接入当前可运行的 llama.cpp / JEV 路径；oMLX 提供配置保存与识别，生产运行接通与共享池参数规则后续讨论，Splash 运行适配也保持后续范围。这避免为参数编辑需求同时改变未接通的运行链路或共享池的服务归属。

2026-10-08 用户明确回复「确认」，共同理解与验收要点已定稿，见 [已确认需求](../requirements/engine-launch-configuration.md)。本记录描述已确认的设计，参数配置功能当前待实施。
