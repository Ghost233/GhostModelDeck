## 问题陈述

用户需要一个管理本机模型和引擎的 Ghost Model Deck。现有界面把模型文件、启动参数、运行进程和委员会成员混在一起，同一个模型的不同用途难以分别保存，客户端也难以明确选择参数组合。

模型库中的“待验证”和其他文件列表增加干扰。单一目录同时承担读取与下载保存职责，不便复用多个已有模型库。配置引用的模型或引擎失效后，用户需要知道缺失原因，并在保留原配置和客户端名称的情况下恢复资源。

用户希望自行选择何时实测。普通启动不应自动执行生成或概率测试，也不应把每个模型跑完整评测集作为管理器交付前置。

## 解决方案

保留“引擎”和“测试场”两个顶层区域。管理器负责关联、设置、下载引擎和模型，独立保存由模型、具体引擎和参数组成的实例配置，提供显式启动、停止、短测试及用户选择的题集测试。

模型库可以读取多个目录，新下载只写入一个保存目录。实例配置与实际运行进程分开管理，同一模型和引擎可保存多份不同参数的配置。公开调用按实例选择，委员会引用保存的实例，资源缺失标红但保留配置。

默认来源保持 JEV b11381（ggml-org/llama.cpp）、llama.cpp 主线、incoai/splash 主线和 jundot/omlx 主线。来源显示真实仓库或本地地址，下载与安装显示进度并允许其他页面继续操作。

本规格依据 2026-10-12 的 Q1～Q19 及共同理解整体确认。它描述目标行为，不表示已有草稿已经完成开发或验收。

## 实现决策

### 模块职责与共同业务入口

- 模型库负责模型发现、目录关联和文件管理，启动参数不再附着在模型资产上。
- 实例管理负责保存、复制、编辑、公开名称、显式启动和停止。实例配置与运行实例分别保存，运行实例记录实际启动版本与参数快照。
- 委员会成员引用实例配置的稳定身份，不依赖显示名称或临时运行标识。
- UI、公开 HTTP、MCP 和既有 SDK 使用同一业务控制及实际运行资源。推理请求不隐式加载模型，不新增测试专用业务入口或第二套模型管理。
- 引擎与模型安装任务在下载页面统一展示。长作业由业务模块持有，不能锁住整个引擎设置和其他页面。

### 引擎与模型发现

- 默认来源为已确认的四项。引擎显示真实仓库 owner/repo；本地来源显示实际地址，不显示“官方”“标准”“Local”等分类标志。
- 保留指定本地或 GitHub Git 地址、克隆、构建和绑定能力。当前源码构建范围沿用已确认的 llama.cpp 及其分支。
- 模型库只展示识别出的模型及基本信息，忽略其他文件或目录，不显示待验证标签。
- 已识别模型格式和基本信息时允许关联与创建实例，不用预设模型名称或架构名单限制选择。实际兼容性由引擎和用户实测判断；真实损坏与缺失不能隐藏，也不能将未知架构直接当作损坏。

### 多目录与文件引用

- 模型库关联多个目录；下载保存位置为单值。
- 选择新的下载目录时自动加入模型库；解除它的读取关联不改变保存位置，不移动或删除文件。
- 按真实文件路径去重，不按内容相同合并不同位置的副本。
- 已关联目录内的文件链接可以解析到明确目标；只读取所引用的模型，不扩展扫描未关联目标目录的其他文件。
- 删除链接项只删除库内链接，不删除外部目标权重。删除前继续执行已确认的在用保护及真实文件校验，不能因解析真实路径而将链接删除变成目标文件删除。

### 实例配置与参数快照

- 实例配置包含稳定身份、显示名称、模型引用、具体引擎引用、完整参数快照及独立公开调用名。
- 同一模型与引擎允许多份配置。每份配置最多一个正常运行实例，启动中的重复操作复用同一作业，已经运行时返回已有实例；多开使用复制后的配置。
- 实例创建时读取目标引擎默认值，保存后固定当前参数。后续引擎默认值变化不回写已保存实例，明确还原时采用当前默认值。
- 不提供“引擎默认／模型独立”模式切换。参数直接显示为滚动列表，修改显示 override，并可点击还原。
- 切换到新的具体引擎时从其默认值开始，不自动翻译或转换旧 CLI。编辑期间分别暂存草稿，切回可恢复；保存只保存当前组合。
- 文本优先、未知参数保留、执行前修正语法错误、模型路径与监听等软件管理字段规则继续沿用。参数解释不能自动重写用户原始文本或冒称已实际生效。
- 参数窗口宽度自适应，底部固定完整命令和取消、测试运行、保存。取消丢弃本次草稿，保存不触发启动。

### 普通启动、用户测试与请求快照

- 普通启动仅执行进程健康、模型加载及实例身份核对，不自动进行文本生成、嵌入或概率探测。
- 健康或加载成功只代表对应运行状态，不代表模型准确率、成绩或全部接口能力经过实测；未知或不支持的接口返回真实错误，不构造假能力或假结果。
- 用户明确点击测试运行时，以未保存参数建立临时测试实例，通过普通公开 HTTP 发起短请求，并在完成、失败或取消后清理。原配置、已有运行实例、公开路由和委员会候选不受临时测试干扰。
- 保存及重新绑定只影响后续启动，已有运行进程和入场请求保留原实际配置，不自动切换或重启。
- 模型或引擎在原位置更新后继续引用原位置，下次启动重新读取当前文件与版本。已运行实例显示其实际启动版本；实际失效如实记录。
- 删除实例配置须先停止运行，只删除配置，不删除模型、引擎源码或编译产物。

### 公开名称与 API 契约

- 标准推理和原生决策公开请求使用实例的公开调用名；委员会使用其公开调用名。运行资源仍按稳定实例身份解析，显示名称不作为引用键。
- 实例和委员会共享唯一公开名称空间。默认公开名转小写，特殊字符归一为连字符，新增重名按可用数字后缀分配，不使用 GUID 或 UUID 后缀。
- 普通显示名修改不改变公开名。用户明确改公开名时提示客户端更新，旧名失效，不保留别名。
- 创建委员会或明确改公开名遇到冲突时先报错，再给出下一个可用名称建议，不能自动改名保存。
- 公开 HTTP、MCP 及既有客户端发现入口引用同一对象和真实运行。原生接口直通及真实失败规则保持，不新增按模型成绩或模型名称决定结果的专用转换逻辑。

### 委员会与资源失效

- 选择当前已有的实例配置作为成员。引用的实例、模型、目录、磁盘或引擎无法找到时，实例及引用它的委员会标红并说明原因，配置和引用保留。
- 单纯未运行显示已保存，不标红，也不显示待验证；资源恢复后重新解析引用。
- 解除模型目录关联或磁盘离线不主动停止已有进程，实际请求继续执行。资源失效期间不能新启动或重启，但仍可停止已有实例；真实进程失败不能继续假装成功。
- 失效实例可改选当前已有模型或引擎，保持实例身份、公开名和委员会引用。
- 删除实例配置后，委员会保留失效引用并标红，不静默移除成员。
- 原有至少一个成员完整成功即可返回、明确报告 partial 的规则保持。不能把部分成员成功描述为全体通过。

### JEV 请求预算（2026-10-13 用户补充）

- JEV 默认整轮请求预算统一为 60 秒，已显式配置的预算保留。实例配置提供正整数秒预算，持久化、复制及改名保持，HTTP/MCP 使用同一已保存值；不改权重或引擎启动参数。保存后用于新请求，已入场请求保留原预算。
- JEV 基础测试和普通基准客户端默认期限为 60 秒，可显式修改。Jevman 固定 2 秒决策与 30 秒 warmup 继续遵守原基准。聊天、嵌入和引擎探测的独立期限不在本次 JEV 补充范围。

### 配置结构与保持的范围

- 应用配置按新结构重新建立，不做旧配置迁移、旧格式兼容或旧公开名别名层。
- 覆盖范围仅为应用配置，模型权重、引擎源码与编译产物、已有历史结果文件保留，不能以配置重建为由清空整个数据目录。
- 只编译、打包和提供 macOS arm64 应用、引擎及配套运行时。固定 Flutter/Dart SDK、原 lockfile、联网依赖解析和宿主机检查保持。
- 测试场和评测属于用户可选功能，不要求每个模型运行全套题集。原生题目、固定 submodule、公开 HTTP/MCP、委员会对照、五项完整基准、Jevman 100 局及无快速试跑保持。
- UI 分批加载和展示摘要，完整 JSON 与结果通过文件路径和 Finder 查看。

## 测试决策

### 测试接缝

沿用用户已确认的最高层级应用业务入口，验证保存、启动、请求、停止、删除和重启后的可观察行为。配置与文件动作通过共同业务控制或真实 UI 发起，推理使用普通公开 HTTP/MCP。

复用现有网络、外部引擎进程/HTTP、SDK socket 和原生窗口 I/O 边界。可控替身只位于这些外部边界，不访问私有方法、不逐行复刻算法、不新增测试专用管理接口。原生 UI、真实进程和短公开请求另做实际 Mac 验收。该接缝与此前已确认的测试边界一致，不引入新的访谈决定。

### 外部行为验收

- 多目录设置重启后保持，下载只写入单一保存位置；选择保存目录自动关联，解除读取关联不影响保存位置或文件。
- 父子目录、目录别名和文件链接不重复展示同一真实文件；不同位置副本独立存在。删除链接不删除目标，目标目录的其他文件没有被扩展扫描；在用及变更文件仍受保护。
- 已识别格式的新架构模型可关联与创建实例；真实坏文件和缺失被如实提示，其他文件与待验证标签不出现在模型库。
- 同一模型与引擎保存两份不同参数配置后可以独立选择。复制拥有独立身份与公开名，重启后仍保持引用。
- 并发或重复启动同一配置只创建一份正常运行资源；已运行再次启动返回原运行实例，不产生额外进程。
- 参数窗口在最小桌面尺寸、明暗主题和已覆盖的文本缩放下可滚动，命令及按钮固定且可操作。恢复、取消、保存及跨引擎草稿切换符合快照规则。
- 普通启动到达健康、加载与身份边界，且没有自动发起生成、嵌入或概率请求。非法身份、加载失败和取消仍失败，不能减少实际运行身份核对。
- 草稿短测试实际使用未保存参数，真实公开 HTTP 请求结果被校验，结束后测试资源释放；已有实例及公开路由、保存文件保持。失败、超时、取消和清理错误不计通过，原始失败不能被收尾错误覆盖。
- 运行中保存参数或重绑资源，不改变已有进程与已入场请求；后续显式停止并启动才使用新配置。原位置更新后新启动使用当前版本，已有运行显示原版本。
- 资源失效时配置与委员会引用变红并保留，已有实际运行和停止仍可操作，新启动被拒；恢复或手工重绑后引用重新可用。
- 运行中删除配置被拒；停止后只删除配置，模型与引擎文件保持，委员会保留失效成员。
- 名称小写与连字符规则、跨实例和委员会冲突、数字后缀建议、显示名独立修改、明确改公开名后的旧名失效均通过真实路由验证。
- 委员会按保存实例选择实际运行资源；部分成员不可用时按原规则返回 partial，失败成员、有效成员及结果与真实输入相符。
- 配置重建不迁移旧结构，不删除权重、源码、编译产物或历史结果文件。
- 测试场数据分批展示摘要，文件和 Finder 入口可用，原始 JSON 不全量渲染到界面。

### 验证节奏与结果

- 主线程推进，不启动子代理。同一作业一份；长作业由主线程执行 sleep 300，实际结束后收取，短检查直接收取。
- 小修复先运行原失败与受影响模块，代码收齐、已知失败关闭后集中完成必要完整门禁，不逐次全量重跑。
- 复用输入、环境和行为未受修改影响的成功证据，不无故重跑真实模型题集。改变结果的评测输入或整批行为按对应功能验收处理，不扩大为每个模型必跑全部题集。
- 验收至少覆盖新对象路由、运行与取消、文件边界、持久化、真实 Mac UI 和必要短公开调用。真实模型成绩不作为所有实例的创建或交付前置。
- 使用固定 SDK 与字体环境，保留布局和字体断言，核对实际 Mach-O 架构。记录源码输入、命令、退出码、业务断言及原始失败；超时、取消、中断和缺证据不计通过。
