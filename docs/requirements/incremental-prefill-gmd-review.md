# GMD 增量预填充接口协作记录

状态：协商中。本文记录 GMD 侧已核对的边界，不声明接口已经实现。

2026-10-28，用户要求 GMD 与 Sentinel 协作开发真实预填充。Sentinel 的 [接口提案 v1](/Users/ghost233/Ghost233Code/GhostCodexSentinel/docs/gmd-prefill-contract.md) 是共同讨论的起点。最终字段和完成语义须与 GhostSplash 的实现证据一致。

## 分工和范围

- GhostSplash 先将预填充适配到当前版本，并提供可关联的原生完成与缓存证据。
- GMD 负责统一入口、模型与运行代次绑定、请求协调和真实结果转发。
- Sentinel 负责采集、维护调度和客户端接入。持续后台预填先用于总结模型；JEV 路径纳入接口和联合验收。
- Sentinel 当前使用 Chat Completions，不要求 GMD 增加 `/v1/completions`。

预填充不等于生成流。每次请求提交完整累计输入；引擎按实际 token 前缀决定是否复用。零预算预填不能替代最终生成或判断。

预期的文本流程是：后台对累计输入 A 预填并确认释放后，冻结需要分析的完整 A+B，直接以正预算提交消费请求。GhostSplash 的源码会对完整输入查找可恢复前缀、处理未复用的尾部，再生成；不要求再对 A+B 单独发一次零预算请求。无可恢复缓存时按完整输入处理。

GhostSplash 当前未提交工作区的隔离 Engine 模拟测试 `testPrefillOnlyThenGenerateWithAdditionalInput` 已覆盖这一精确顺序并通过：A 的 2113 个模拟 token 中实际恢复 2112 个，第二次请求处理剩余的一个 A token 和 64 个 B token 后生成，并确认两次请求释放。该测试使用模拟执行器和直接 token 输入，不覆盖 HTTP、真实 tokenizer、Metal 或真实模型；本轮没有 Tiel Coder 加 DFlash2 实测，目标侧命中也不能证明草稿侧命中或无回退。

为最终请求预留的是操作登记容量，不代表额外的 GPU、内存或上下文容量。当前预填仍在运行或取消尚未确认释放时，同盐请求须等待；实际计算资源不足时仍按真实容量排队或拒绝。本轮不额外引入冷回退产品分支。

## 协商要点

1. 确定引擎对单次预填、最终生成和判断分别返回哪些计数，及其与原生请求身份的映射。Tiel Coder 与 DFlash2 的目标侧和草稿侧证据分开记录。
2. 确定输入摘要、缓存提交边界和运行代次的真实来源。任何来源不可用时，能力保持未确认，不填假值。
3. 确定请求状态和取消如何跨 GMD 与 Splash 关联。断连或取消被接受不等于原生计算终止，也不等于缓存占用释放。
4. 确定操作 ID、凭证、重试、保留期和重启后的行为。不同输入不得复用同一操作；旧代次不能静默转到新模型。
5. 确定 System One 状态预填与后续问题的模板前缀。双向编码器和没有完整实现的委员会不声明支持。
6. 确定零预算响应的公开结构及旧引擎拒绝方式。新旧能力分别声明；空结果不能进入普通生成或 JEV 答案路径。

## 最小完成和终态映射候选

以下为三方协商候选，仍需 GhostSplash 证明安全接续时点；不是已公开的协议。

1. GMD 接收预填时，登记调用方操作 ID、凭证摘要、模型、运行代次、缓存盐摘要和请求摘要。GMD 自己拥有这份登记，并把操作关联到 Splash 实际运行代次和原生请求 ID。
2. 文本零预算和 JEV 状态预填使用各自的结果类型。GMD 只有在获得引擎的完整输入处理、零生成和同缓存可安全接续的证据后，才返回完成。两种响应的外部 JSON 形状可以转换，不把空结果当普通生成或答案。
3. 成功结果可先传递已确认含义的原生输入总量、`matched_prompt_tokens` 和 `deduplicated_tokens`。不要求用估算值补齐引擎尚未提供的 token 摘要或未来可复用数量。JEV 多题的原生请求和计数分别关联，不能把重复状态相加当作单份前缀。
4. 客户端断连不删除操作记录。取消只请求结束，公开状态保持非终态且不允许同缓存接续，直到收到可关联的原生终态与安全接续证据。重启或连接丢失无法确认时保持未知；不得从 GMD permit 释放推断引擎空闲。
5. 同一操作的重试须核对凭证、请求摘要、模型、代次和缓存盐。不同输入复用操作 ID 明确冲突。最终生成或判断使用新操作 ID，并保持已确认的缓存绑定。

安全接续指原生操作不再修改同一缓存和模型状态；不要求等待无关的全引擎后台清理。缓存提交指当前运行中可供后续请求复用，不保证已经写盘或跨重启保留。以上边界须由引擎实现和测试证明。

公开操作 ID 候选采用 `gmd1.<运行代次摘要>.<签发毫秒>.<凭证摘要前 128 位>`。每个操作独立生成 256 位随机凭证；摘要输入为 UTF-8 `gmd-prefill/1:operation-token`、单字节 `00` 和十六进制解码后的凭证。首次登记接受过去 10 分钟和未来 1 分钟内的 ID。已有记录先核验凭证及绑定，再处理重试；不能因超时将旧操作当作新操作。

公开运行代次须包含每次 GMD 重开后不可复用的启动身份。进程内时间水位不后退；GMD 重启后的旧代次 ID 不能首次登记。未确认的旧引擎占用另行保护，不能因为代次更新而清除。

三方接入的目标是在支持预填的模型行 `capabilities.prefill` 下提供 `runtime_generation` 和 `operation_policy`：

```json
{
  "id_format": "gmd1",
  "time_basis_ms": 1793157880100,
  "past_window_ms": 600000,
  "future_tolerance_ms": 60000
}
```

数值仅为示例。`time_basis_ms` 是 GMD 当前进程非递减时间的快照；客户端可结合单调时钟计算收到快照后的经过时间，快照过旧或运行代次改变时重新发现。公开的 `runtime_generation` 为匹配 `[A-Za-z0-9._~-]{1,128}` 的不透明 ASCII 标识，须由可信启动身份与实际运行绑定生成，不能直接使用客户端提供的代次，也不原样暴露本地路径。生成 ID 使用实际公开代次的 UTF-8 SHA-256 摘要、该时间基准和上述凭证摘要。这些字段目前仅在隔离 fixture 的合成模型上公开，当前正式运行的 GMD 未开启该协议。

已确认释放的结果在本进程内至少保留到 ID 首次登记窗口结束和操作终态后 10 分钟中的较晚时间。终态后时长按独立单调时钟计算，不能因为登记逻辑时间向前跳而提前淘汰。过期 ID 不得重新执行。进程重启后，如无法恢复结果，返回未知。尚未确认释放的记录不按时间淘汰；达到容量上限时明确背压，并为最终生成与判断预留容量。

账本重启后，目前只有原服务身份与原生代次匹配的可信终态证据能够解除未知操作的占用。原服务仍可访问时，需要原操作 ID 和调用方持有的原凭证才能查询；账本中的凭证摘要无法还原凭证。尚需实现可验证的旧引擎退出恢复：证据须关联准确的进程及原生代次，处理 GMD 重启和 PID 重用，证明相关进程及其后代确已退出，并核验其不能再异步写入相关状态。代次变化、PID 不存在、进程组为空、文件锁可获取、404 或超时不能单独证明释放。在恢复路径完成前，未知状态可能持续占用容量。

GhostSplash 的只读核对确认，当前没有可跨 GMD 重启验证全部相关进程退出的持久凭证。受信监督者和绑定运行身份的退出回执只是候选设计，尚未实现或验证。如果未来取得可信释放证据但原业务结果已丢失，协议须分别表达 `state: unknown`、`terminal: false` 和 `lease_released: true`：允许在新代次另建操作，不将旧结果说成完成或取消。当前账本把释放与终态绑定，尚不能表达这种恢复结果；现阶段继续保守保持占用。

当前正式运行的 GMD 没有公开错误可证明操作未登记或未向原生提交；客户端对没有有效证明的 4xx、5xx、断连及 404 均须保留原操作身份并按未知处理。隔离 Gateway 仅在已认证操作、确认不存在同身份的既有在途登记，并确认原生提交未开始时返回明确证据。普通冲突或上游拒绝不能自动推断这些条件。

工作区的登记组件已能在执行配额不足时先保存绑定到操作及凭证摘要的独立拒绝记录，再返回该操作未向原生提交的证据；记录在重启后仍可查询，同 ID 不能重新派发，且不占消费执行配额。隔离 Gateway 已通过 HTTP 测试验证这条路径，正式运行应用尚未装配。拒绝记录已满时，仅符合下述水位条件的当前代次操作能取得身份级证明；写入失败或条件不足时不能提供安全证明。隔离测试中的登记容量预留不代表真实模型拥有额外 GPU 或上下文资源。

为避免拒绝记录池耗尽导致合法操作无法取得未提交证明，登记组件已加入单调首次登记拒绝水位：已登记操作先按原绑定核验；对当前启动身份和合法时间窗内从未登记的操作，在水位持久生效后才证明迟到提交不会被派发。登记前取消需要证明 ID 与请求凭证属于同一操作，因此 ID 的随机段使用每次独立生成的随机凭证的域分隔摘要。组件测试覆盖了登记与水位的先后顺序、错误凭证、存储失败、拒绝池耗尽、重启和消费容量预留。

水位只能证明操作身份未被登记及不会迟到派发，不能声称已核验模型、盐或请求正文；已登记的拒绝才有这些绑定。组件提供当前启动身份的代次生成，须从可信的实际运行实例生成并核对，不能相信客户端声称的代次。公开提交、查询、取消、原生终态校验和进程内重放已在依赖注入的隔离 Gateway 中接通。主应用源码已开启服务装配，但只对当前 Splash 实例明确声明并通过身份核验的路径报告支持；旧版本和缺失或无效声明保持不支持。当前运行中的应用未更改。跨进程崩溃及真实模型场景也未验证，不能将隔离测试当作真实模型验收证据。

隔离 Gateway 中的容量拒绝证明有两种范围。完整绑定的拒绝返回 `proof_scope: bound`，包含该操作的公开模型及缓存盐摘要；仅由拒绝水位证明身份的拒绝返回 `proof_scope: identity_only`，不包含模型或盐摘要。两种均包含原操作 `request_id`、可信 `runtime_generation`、`state: rejected`、`terminal: true`、`lease_released: true`、`native_dispatch: not_started`，以及 `error.code` 和 `error.stage: admission`。直接容量拒绝的代码为 `capacity_unavailable`；以后通过水位查询时，无法恢复具体原因，代码为 `not_admitted`。无效请求和同盐占用的直接拒绝分别可返回 `invalid_prefill_request` 和 `prefill_context_busy`。身份级证明只说明本操作未提交，不能证明其他同盐操作已释放；普通错误、404 或条件不足时不能自行推断证明成立。

已登记但尚未派发的操作被取消时，隔离控制面返回 `state: cancelled`、已确认终态及释放，并包含空的 `children` 数组。原生取消尚未确认时保持非终态；在未知状态收到取消请求时，账本持久保留取消意图，后续确认原生终态也不会重新发布晚到结果。

独立的公开请求解析器已覆盖文本零预算、正预算及 JEV 状态预填／问题判断的输入校验，并接入隔离 Gateway。预算别名不能以 `null` 或正数覆盖显式零预算，普通判断仍使用既有题型校验。隔离测试中的追踪与普通请求按实际同一 Splash 实例、同一显式 `cache_salt` 原子协调；无盐及其他独立盐的普通请求不被全局串行化。普通请求异常或原生释放未确认时保守保留占用。

已认证操作的失败状态拟提供独立的 `error.code`、`error.stage` 和脱敏的通用 `error.message`，不包含输入正文、凭证、私有地址或原生别名。只有证据能确认时才给出具体阶段，否则标记为未知；查询不到原操作不能伪造失败原因。错误枚举及完整响应尚待公开路由实现并与 Sentinel 测试确定。原生子请求继续保留真实结束原因，取消、失败和空子请求均不能当作成功预填。

## GMD 前置改动

GMD 在 `/api/v1/models` 的现有文本和决策模型行增加 `capabilities.prefill`。新源码只对 Splash 实例明确声明操作跟踪及对应路径支持时返回 `supported: true`；否则返回 `supported: false` 和 `reason: gmd_prefill_unavailable`。Embedding 行保持原样。

不支持声明只表示该实例尚未确认完整预填路径，不表示普通生成或判断不可用。模型行本身仍遵循现有容量发现规则；缺少模型行或能力字段表示未声明。

工作区还包含原生操作提交和状态读取器、登记账本及操作 ID 的基础实现。Splash 提供持有现有运行实例许可并核验实例身份的追踪接缝，服务适配器已连接该接缝；主应用源码开启服务但仍依赖真实 Splash 的按实例能力声明。本地许可释放不代表原生缓存已释放。账本仅淘汰已确认终态且超过重放保留期的记录，结果和原生终态证据保存在当前进程内；重启后普通在途操作恢复为未知。账本不能单独作为确认删除引擎记录的依据。

跨项目隔离测试使用 GhostSplash 当前工作区的真实 HTTP 层和受控原生替身。GMD 提交中文零预算请求并读取零输出、原生身份和释放证据；请求以 UTF-8 字节长度设置 `Content-Length`。该检查不代表真实 GPU、Tiel Coder 或 DFlash2 已通过。

## 可验证目标

定稿后先用受控外部引擎接缝验证公开 HTTP、运行代次、同盐串行、重复提交、错误凭证、取消和晚到结果。旧引擎、未知能力及不支持的模型须明确拒绝；普通生成、普通 JEV 和现有 MCP 行为保持。

真实联合验收须覆盖 Tiel Coder 加 DFlash2 的累计输入预填与最终生成，以及受支持 JEV 的状态预填与最终判断。命中证据来自引擎实际计数；D3 lite 和 mini 的不支持结果单独保留。当前尚无这些真实组合的本轮验收结果。
