## 问题陈述

Ghost Model Deck 当前关联引擎后，只保存路径、实际版本和内容指纹，模型启动参数由软件固定拼装。用户无法在应用中调整上下文、GPU、内存或缓存等选项，也无法为不同模型变体保存不同的启动配置。

引擎参数数量多，版本之间存在名称、别名和语法差异。用户需要自由填写参数，并获得尽力识别的提示，同时看清最终实际采用的启动命令。软件不能因识别不完整而拒绝新参数，也不能在解析时自动改写用户的原始文本。

## 解决方案

为每个登记引擎提供引擎默认启动配置，并允许用户按模型变体与具体引擎登记项保存模型启动覆盖。两处使用相同的常用参数表单、参数文本与最终命令预览编辑器。

自定义参数以文本优先，重复定义的表单项标红提示但仍可启动。软件管理的模型、监听与标识字段继续由软件生成。内置规则结合当前版本帮助信息尽力识别；未知内容保留，语义问题只提示，实际启动由引擎判断并报告结果。完整命令预览与启动参数来自同一份生成结果。

保存只影响后续启动。引擎升级或解除关联保留调优配置，用户可以切换继承与独立配置，并在重新关联后手动恢复。本次完整应用启动参数的范围为当前可运行的 llama.cpp / JEV；oMLX 提供配置保存与识别，并维持现有生产运行限制。

## 实现决策

- 使用项目已确认的领域词汇：引擎默认启动配置、模型启动覆盖、启动参数文本、最终启动参数、未关联启动配置；遵守已接受的配置层级 ADR。
- 扩展现有引擎配置与公开启动控制，预览和执行复用同一个参数生成结果。保留现有模型核验、引擎身份核验、生命周期和资源所有权要求。
- 持久保存引擎登记身份、默认表单值、原始参数文本，以及按模型变体与具体引擎关联的独立配置和继承选择。当前启动参数不构成新的模型或引擎运行实例。
- 模型独立配置是一整份表单值与文本的副本，不对引擎默认配置做逐参数差异合并。未启用覆盖、启用独立空配置、暂时恢复继承但保留独立内容分别表达。
- 当前可运行引擎的初始表单沿用现有软件参数值，文本初始为空。用户可修改或清空表单项。
- 引擎管理页提供默认参数配置入口；运行模型流程提供继承选择和独立配置编辑。两处复用相同编辑器。
- 用户填写表单和参数文本时不强制双向同步或自动改写。对自定义参数，文本中的同名或已识别等价别名优先于表单，表单对应项标红并说明已被文本覆盖。
- 删除文本中的覆盖项后，仍保存的表单值重新参与生成。未知参数、原文格式及文本中的重复项不因识别结果被删除或重写；重复文本参数由引擎解释。
- 软件管理字段优先于用户配置。识别到用户输入中的模型路径、监听地址/端口、对外模型标识等受控项时，生成执行参数时剔除并明确提示实际软件值；原始文本保留。
- 参数识别结合内置规则和当前安装/关联版本的帮助信息，尽力补充名称、别名及说明，至少覆盖内置支持的参数。识别限制作提示，不被视为用户必须修正的配置错误。
- 参数文本只填写参数，可执行文件和子命令由软件生成。保持现有参数数组执行方式，不依赖 shell 展开；拆分后保留参数顺序、重复项、空格值和参数边界。
- 未知参数可以传给引擎，已知参数的语义错误也只提示。引号未闭合等无法拆分参数的文本允许保存，但启动前要求修正并指出位置；此时不展示虚假的可执行命令。
- 完整预览包含可执行文件、软件管理字段和最终自定义参数，支持复制。编辑阶段动态字段明确标注启动时分配，启动后保留该次实际使用命令，并与实际进程参数核对。
- 保存配置仅影响后续启动，不自动重启已有实例。正在运行的实例仍显示和使用该次实际参数，立即应用由用户手动重启。
- 桌面与已有 SDK 启动入口共用配置及业务控制；已有请求入口不新增一套配置合成或进程管理逻辑。
- 引擎版本改变后保留原表单与文本，刷新识别并提示差异，不自动重写、重置参数或放宽已有安装/关联核验。
- 解除关联保留未关联启动配置。重新关联后由用户手动选择恢复默认配置及对应模型覆盖，不能因同一路径、名称或家族相似而自动套用到其他登记项。
- 本次将最终启动参数应用于当前可运行的受管或关联 llama.cpp / JEV 路径。oMLX 提供配置保存与识别，并准确呈现当前生产启动尚未接通的限制；不因保存配置而启用或宣称运行能力。

## 测试决策

- 用户已确认沿用现有外部进程 I/O 接缝，从真实配置编辑/保存及公开启动入口驱动，记录实际交给进程的参数，验证与最终预览一致。核心解析、配置选择、优先级合成和持久化保持真实，不增加模拟核心逻辑或访问私有方法的测试接缝。
- 复用现有引擎目录、模型运行对话框和引擎启动测试的真实业务组合及外部进程 I/O 替身。只替换进程、帮助输出、日志等 I/O；对替身传入的实际参数、公开状态与保存内容作断言。
- 复用 SDK 真实 Unix socket 往返测试，由启动模型集合进入同一公开启动路径，确认桌面与 SDK 使用同一配置，并保持幂等、取消和收尾边界。
- 从界面验证表单可编辑、文本优先、等价别名覆盖提示、覆盖项删除后的表单恢复、未知/已知语义提示不阻止启动，以及无法拆分文本可保存但不能启动。
- 验证拆分和执行保留带空格值、引号含义、等号表达、参数顺序及重复项；对未识别的重复或新选项不按猜测做语义合并。
- 验证受控字段被剔除并有提示，原文保留，最终模型/监听/标识来自软件管理，已有模型和引擎身份核验要求仍有效。
- 验证模型变体与具体引擎之间相互隔离、整份配置独立、继承切换保留内容、独立空配置区别于未覆盖、应用重启后恢复、升级后保留、解除关联后手动恢复。
- 验证帮助输出可以补充识别，读取失败、部分识别或版本差异只产生提示；不能靠成功读取帮助信息声称参数已在真实引擎生效。
- 验证配置保存不会停止或重启已有实例，既有实例实际命令保持原值，后续启动使用新值，启动失败报告实际进程错误而非虚报成功。
- 在 Mac 上完成真实 llama.cpp / JEV 启动验收，证明最终参数实际生效、命令记录与执行一致、软件管理字段正确及资源收尾。通用测试和构建不能代替该验收；使用原有模型文件并保留其完整性与所有权。
- 对 oMLX 验证参数保存、识别和界面运行限制，不以独立模型池测试或驱动器证据冒充生产 GUI 已接通；本规格不要求 oMLX 模型加载验收。
- 按项目检查入口完成格式、静态分析、相关与完整回归、Mac 构建，并保留最终输入、真实退出码、失败及修复证据；未执行或受限项目明确报告。

## 范围之外

- oMLX 生产模型启动接通、共享池进程级参数与每模型参数映射、重启池及关联安装运行归属。
- Splash 的关联、模型输入适配、运行进程管理和真实模型验收。
- 为未知引擎自动生成完整运行适配器，或承诺任意帮助文本都能推导出完整参数语义。
- 输入并执行完整 shell 命令、管道、变量展开或命令替换。
- 因解析结果自动重写原始文本、强制同步表单、拒绝所有未知参数或对已知语义错误一律阻止启动。
- 保存配置后自动重启已有模型，或自动把未关联配置迁移到其他引擎登记项。
- 新增远程配置管理协议、第二套模型管理、隐式模型下载或改变既有模型与引擎所有权。
- 先前独立完成的品牌名称及 SDK 菜单栏许可接入，不作为本参数规格的新实施范围。

## 补充说明

来源为 2026-10-08 已完成 Q1–Q21 并整体确认的需求讨论，配置层级与边界已写入领域决策记录。测试接缝也已由用户明确确认。

当前参数功能尚未实现。现有启动对上下文、批量、并行、GPU 层数和设备传入固定值，读取帮助信息主要用于关联核验；这些现状不代表已有通用参数编辑或自动表单生成能力。

oMLX 内部真实模型池代码与独立验收存在，但当前生产主程序的模型库依赖和 GUI 通用启动尚未接通，多模型还共享服务进程。本规格遵循用户选定范围，完整运行接入与参数归属保持后续需求。

本规格发布为规范父工单，后续实施切片与验收据此建立；工单的 ready-for-agent 表示规格已具备代理实施条件，不表示功能已经完成。
