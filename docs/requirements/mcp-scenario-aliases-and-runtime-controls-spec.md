## 问题陈述

用户希望用少量稳定的模型名字调用后台实例或委员会。现有 MCP 模型列表直接暴露后台对象，缺少固定的场景配置。场景说明、模型名字和实际绑定容易混淆。

模型、引擎和实例的卡片展示不便横向比较。运行监控占用空间较多，用户希望直接看到各实例的推理并发、排队、阶段和处理量。速度曲线大多接近直线，用户只需要最近一分钟的平均速度。

用户还需要统一控制全部引擎实例，并明确选择应用启动时是否自动开启总开关、哪些实例自动启动。恢复上一次总开关状态不符合用户预期。

## 解决方案

提供四个固定场景槽位。场景显示名称、模型名字、后台绑定和启用状态可编辑。HTTP 与 MCP 共用模型名字，MCP 默认仅发现启用且可用的场景模型，HTTP 列出全部可用模型。

模型、引擎和实例改为可搜索、筛选、排序和分页的表格。运行监控按实例显示两行：第一行展示推理槽位和请求进度，第二行展示模型、引擎、累计 token 和最近一分钟的平均速度，移除曲线与详情。

引擎总开关关闭时取消全部实例工作并释放运行资源；开启时启动勾选了自启动的实例。保存独立的总开关自启动配置和实例自启动列表，不恢复上一次总开关状态。

## 实现决策

### 场景、模型名字与统一路由

1. 固定四个场景槽位，不提供新增或删除。首次预建并启用，默认显示名称为短上下文、长上下文、短上下文＋视觉、长上下文＋视觉。
2. 每个槽位保存独立的显示名称、模型名字、启用状态和后台绑定。显示名称可用中文，例如“4k上线+视觉”；模型名字例如 `fast-v`。名称和绑定由用户配置，不自动挑选对象。
3. 后台绑定指向已保存实例或委员会，委员会仍引用保存的实例。绑定使用稳定对象身份，不通过文件名、中文显示名或当前进程端口重新猜测对象。
4. HTTP 与 MCP 共用模型名字和解析规则。实际实例、委员会与场景虚拟模型都通过必填的 `model` 选择。复用现有模型名字注册和唯一性规则，不建立 HTTP 专用或 MCP 专用命名空间。
5. 场景显示名称变化不改变模型名字。更换后台绑定可保留模型名字；已有请求沿用入场时确定的绑定与运行代次，不把执行中的请求转交给新对象。
6. MCP 默认模型列表只返回四个场景中已配置、启用且可用的模型。HTTP `/v1/models` 返回全部可用的实际实例、委员会及场景虚拟模型，按唯一模型名字表达。
7. 默认 MCP 列表范围不等于直接调用的白名单。已知有效的实际模型或虚拟模型名字仍可调用；已有各入口的能力与协议限制继续适用。
8. 单实例需已运行且可用；委员会至少一名成员实例可用即可被发现。没有可用成员时不返回。未配置、停用或失效的场景不作为可用场景模型返回。
9. 保存配置、列出模型和收到推理请求都不隐式启动实例。调用时重新核对绑定与运行身份；不可用、身份失效或上游调用失败时保留真实错误，不自动借用其他实例或换模型。
10. “视觉”仅为用户的场景定义。场景文字不决定能力准入、协议切换、成员筛选或特殊失败分支。本轮不因该文字扩展图片协议；通用委员会 partial 规则保持。
11. MCP 保留现有结构化判断工具及 choice／score／noul 结果。服务器 instructions 与工具 description 使用固定模板，结合当前配置生成模型名字、用途和上下文。客户端重连或刷新后取得最新说明，不承诺强制刷新宿主缓存。

### 上下文与参数生效

12. 上下文由实例生效的启动配置确定，不采用模型理论上限，也不要求先启动一次或探测进程才能确定初始容量。
13. 单实例取自身容量；委员会按全部配置成员的生效容量取最小值。成员暂未运行仍计入，不随成员启停调整容量。
14. 实例参数编辑窗口即时预览本实例、引用它的委员会及场景的“原容量 → 新容量”。预览不修改保存配置或运行状态。
15. 取消编辑不保存；保存仅更新待应用参数，不自动重启。运行中的实例重启应用新参数后，才更新本次生效容量及关联委员会、场景的有效容量。

### 三张管理表

16. 模型表每个模型变体一行；引擎表每份安装或关联条目一行，未安装的默认引擎也保留；实例表每份保存配置一行。同一模型的不同实例不合并状态或操作。
17. 默认列如下：

| 表格 | 默认列 |
| --- | --- |
| 模型 | 模型名、格式、量化、大小、所在目录、操作 |
| 引擎 | 引擎名、仓库或本地路径、版本、状态、操作 |
| 实例 | 实例名称、模型名字、对应模型、引擎、上下文、并发、自启动、状态、操作 |

18. 常用操作在行内，其余在“更多”。提供搜索、状态筛选和表头排序。查询、筛选、排序和分页作用于同一数据结果，不能仅处理已渲染的当前页。
19. 保留分批加载与惰性展示。布局使用可用窗口宽度，宽度不足时横向滚动，不为表格设置固定最大内容宽度。不一次性展开全部数据或原始 JSON；完整数据继续通过已有文件和 Finder 入口查看。
20. 表格展示继续使用真实状态和错误，不恢复“待验证”、其他文件／目录、完整性使用门禁或“未关联启动配置”功能。引擎和模型的下载仍归下载页面管理。

### 两行运行监控

21. 每个运行实例独立占两行。场景和委员会请求计入实际执行的底层实例，不创建重复的监控实例或重复累计 token。
22. 第一行按推理并发槽位画格子。各格显示空闲、prefill 或 decode，以及当前请求处理数量；请求完成后槽位复用。HTTP 接收容量不能替代推理并发槽位数。
23. 排队数量独立显示，不占额外格子。例如 4 个执行、3 个排队，显示 4 个执行格子和“排队 3”。
24. prefill 总量已知时显示已处理／总量，未知时只显示已知处理数量；decode 显示已生成 token 数，不估算完成百分比。
25. 第二行显示模型名字、引擎、本次运行累计输入／输出 token，以及最近 60 秒滚动平均的 prefill／decode 速度。两种阶段分别计算，不继续采用引擎全会话均速冒充一分钟均速。
26. 一分钟指标必须来自窗口内可信的阶段计数、耗时或采样；过期数据退出窗口。统计隔离实例与运行代次，重启后重新统计；缺少足够数据时遵循缺失值规则，不混入其他实例或上一次运行。
27. 未知阶段显示“运行中”，未提供的数量或速度显示“—”，不伪造为 0。读取失败或晚到旧代次数据不能覆盖当前状态。缺失监控数据不改变实例运行状态，不阻止启动或调用。
28. 移除运行监控的曲线、展开详情与详情入口。仅为滚动平均保留有界数据，不保留无用绘图历史。刷新和绘制限于当前需要展示的数据，避免全列表重建或后台无界累积。

### 总开关与自启动

29. 引擎区提供总开关，共用业务控制统一约束全部启动入口，包括手动运行、自动加载、参数草稿测试及 SDK 发起的启动。界面禁用按钮不能代替业务入口的限制。
30. 关闭总开关先关闭新启动及请求准入，取消执行中、排队、启动中和测试运行中的任务，停止全部 GMD 受管实例并释放资源，不等待推理完成。取消不能记为成功。
31. 总开关关闭期间，晚到启动结果不能重新发布为可用，旧停止任务也不能误停后来新一代实例。重复关闭应能安全收尾；清理失败如实显示并保留重试能力，不能虚报资源已释放。
32. 关闭不退出 GMD，不停止 HTTP／MCP 接入，不删除实例配置、模型文件、引擎安装或历史，也不停止外部应用拥有的进程。
33. 打开总开关时，仅自动启动设置了自启动的实例，未设置的保持手动启动。所选实例并发执行，各自显示状态和结果；已运行或启动中的同一实例跳过重复启动。
34. 某项失败不阻止其他实例启动。不自动换模型，不反复重试，由用户手动重试。
35. 设置页保存“是否随 GMD 启动自动开启总开关”和实例自启动列表。实例表的自启动选择与设置页使用同一权威数据；复用已有启动集合，不建立第二份列表。
36. 当前总开关状态不持久化。应用启动时仅根据“总开关自启动”配置决定是否开启，不能恢复上次手动状态。手动切换总开关不修改自启动配置；正常退出清理也不修改配置。
37. 全新安装默认不自启动总开关，新建实例默认不勾选自启动；保留已有保存的选择。总开关关闭时，即使实例勾选自启动也不能加载。
38. 自启动选择是保存的配置。保存或取消勾选本身不启动或停止实例；应用启动或总开关由关到开时使用当前选择。资源失效沿用实例的现有错误状态，不自动改绑。

## 测试决策

### 已确认的测试接缝

沿用用户已确认的最高层级接缝：应用共用业务入口承载实例、模型名字、场景、委员会与总开关；界面、真实 HTTP、MCP SDK 和现有 SDK 都调用这份运行图。观察公开输入输出、可用列表、状态、保存结果、请求取消及资源变化。

继续使用现有外部引擎进程／HTTP、文件 I/O、原生窗口和 SDK socket 边界。时间窗口用可控时间验证，不等待真实一分钟来证明算法。不得新增私有测试业务入口、复制模型管理逻辑或以 mock 内部调用次数代替外部行为。

已有的实例公开 HTTP、MCP 保存实例绑定、同一安装独立启动、监控数据缺失、代次替换、分页以及设置窗口测试可直接扩展。曲线专用断言随移除曲线改为新契约断言；保留缺失值、分页、字体、布局和生命周期断言。

### 必须覆盖的外部行为

| 编号 | 验收行为 | 通过条件 |
| --- | --- | --- |
| A01 | 四个初始场景与编辑 | 只存在四槽，默认启用且可改名；模型名字和绑定由用户配置，保存重开一致 |
| A02 | 默认发现范围 | MCP 仅返回启用且可用的场景；HTTP 返回全部可用实际和虚拟模型；无可用实例时不伪报就绪 |
| A03 | 统一模型名字 | 同名经 HTTP／MCP 解析到同一保存绑定；中文场景名不混作 model；已知有效实际模型名字可直接调用 |
| A04 | 绑定与在途快照 | 改名或换绑定后新调用使用新配置；在途请求不换实例，不借用同模型的未绑定实例 |
| A05 | 委员会可用性 | 至少一成员可用即可发现，无可用成员不返回；保留原 partial 与真实失败 |
| A06 | 场景文字边界 | 改“视觉”等说明不触发能力探测、路由切换、成员筛选或额外模型请求 |
| A07 | 固定模板说明 | 服务器说明反映当前场景名字、用途和容量；重连／刷新可取得新内容 |
| A08 | 上下文与预览 | 单实例取生效配置，委员会取全部成员最小值；成员启停不改容量；预览覆盖关联对象且可取消 |
| A09 | 参数重启生效 | 保存不打断实例、不立即扩大对外容量；重启成功应用后再更新，不用失败或旧代次假报生效 |
| A10 | 三表行与列 | 变体、引擎条目、实例分别成行；默认列完整，同模型多实例可区分 |
| A11 | 搜索排序分页 | 搜索、状态筛选、排序与分页结果一致；只批量显示当前所需摘要，窄窗口可滚动且操作可达 |
| A12 | 两行与并发格子 | 实例独立两行，4 个推理槽位显示 4 格；请求完成复用，虚拟模型不重复累计 |
| A13 | 阶段与排队 | prefill／decode 和处理量正确，排队独立显示；HTTP 容量不冒充推理槽位 |
| A14 | 缺失监控数据 | 显示“运行中”或“—”；不伪造零和百分比，不影响真实请求 |
| A15 | 一分钟速度 | 可控时间下窗口内数据计入，超过 60 秒退出；两阶段、实例及运行代次隔离，重启重置 |
| A16 | 移除曲线详情 | 两行之外无曲线、展开详情或详情入口；采样有界，旧数据或隐藏页面结果不覆盖当前状态 |
| A17 | 总开关关闭 | 在途、排队、启动中、测试运行均取消，实例停止；窗口和 HTTP／MCP 接入仍可操作 |
| A18 | 准入和关闭竞态 | 所有启动入口均受约束；关闭与启动／重复关闭／重新开启交错时，不出现晚到就绪、重复实例或误杀新代次 |
| A19 | 自启动配置 | 总开关自启动和实例选择独立保存；不恢复上次总开关状态；默认都关闭 |
| A20 | 开启与并发启动 | 只启动已选实例，已有运行或启动幂等复用；单项失败不阻塞其他项，不自动换模型或循环重试 |
| A21 | 配置与资源保留 | 手动开关、正常退出和失败不改自启动选择，不删除模型／引擎／历史，不停止外部资源 |
| A22 | 原生短流程 | macOS arm64 真实界面可配置、启动、发现并短调用；切换总开关后真实请求中断，受管 PID／端口释放，重新开启只启动选定实例 |
