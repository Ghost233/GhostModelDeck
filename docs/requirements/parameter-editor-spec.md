## 问题陈述

用户需要在 Ghost Model Deck 中，为 llama.cpp 和当前自定义 Splash 配置模型运行参数。已有界面把部分枚举、开关、模型资源和列表留在高级启动参数文本中，用户必须查找 CLI（Command-Line Interface，命令行接口）语法，才能完成常见设置。

草稿模型还可能引用已删除的临时目录，或依赖安装目录自动寻找候选。用户难以判断自己选中了什么，也无法区分文件检查通过、主模型就绪和草稿实际启用。

生成参数与加载参数的生效时机不同。用户需要按实例配置保存生成默认值，并让下一次请求采用新值。同时，当前运行的模型应继续使用已加载的资源。仅保存配置、显示控件或通过测试替身，都不能证明实际引擎已经按要求运行。

## 解决方案

采用用户选择的 A 方案：在现有实例配置入口使用分组侧栏。llama.cpp 和自定义 Splash 都提供符合参数类型的控件，高级分组也可直接编辑。启动参数文本保留为可选入口。

每份实例配置保存自己的加载配置、实例生成默认值和显式草稿选择。生成默认值从下一次请求生效；加载和草稿资源配置在下次成功启动后生效。界面分别显示待应用配置和当前推理实例的实际状态。

草稿模型由用户明确选择。GMD（Ghost Model Deck）检查资源及所选原生引擎的兼容性，核实实际启用结果。失效、不兼容或未实际启用时，显示来源和失败原因，不静默改选其他资源。

## 实现决策

### A 方案与控件语义

正式界面采用 Flutter 原生分组侧栏。实例配置编辑与引擎默认启动配置编辑复用参数控件。实例生成默认值与测试场单次覆盖复用生成参数控件。

布尔值使用开关或三态选择，枚举使用下拉框，数值提供精确输入，适用时配合步进或滑块。容量和时长提供单位选择，字符串列表提供增删操作，资源提供原生选择器，结构化输出提供格式选择和有校验的对象编辑器。

响应长度限制、Top P、Min P 和重复、存在、频率惩罚等可选项，分别表达启用状态和关联数值。恢复继承与明确关闭具有不同语义。关闭过滤或惩罚时，采用所选引擎的中性值或关闭规则，不以省略字段冒充关闭。

控件显示继承或覆盖状态、生效阶段、文本优先关系、版本适用性及失败原因。参数存在依赖时，显示适用状态与说明。文件选择取消不覆盖原选择；连续输入、粘贴和中间编辑保持正常焦点与光标行为。

### 参数范围与当前引擎能力

llama.cpp 与 Splash 分别维护参数目录和原生适配。已知可调参数都可通过控件配置；当前引擎帮助中额外识别的选项也提供参数项。软件管理字段显示归属，不作为普通用户输入。

Splash 的启动与运行参数以当前自定义版本已有 CLI 为准，覆盖其 40 项共享声明和基础启动字段。范围包含上下文、内存、KV 和状态格式、空闲释放、SSD 缓存、服务预算、ANE、功耗恢复、提示查找、compact、编码器、电源、网络及认证设置。

生成设置覆盖当前原生请求支持的温度、Top K、Top P、Min P、惩罚、随机种子、停止字符串、EOS、结构化输出和思考设置。Splash 另按原生契约提供请求优先级、时限和缓存隔离等调度设置。

参数目录核对名称、别名、类型、枚举、取值范围、默认来源、软件管理归属与依赖关系。重点关系包括持久缓存与磁盘预算、ANE 行数与实际编译上限、功耗参考与百分比、编码器用途及 compact 资源。当前帮助未确认支持时如实提示，不把未知当成支持。

界面不把参考截图数值或源码编译默认值冒充当前二进制的实际值。原生仍负责最终兼容性和运行约束，语义错误保留可解释的失败结果。

### 实例配置与保存模型

每份实例配置保存完整的模型、具体引擎安装与参数组合。参数分为加载配置、实例生成默认值和显式草稿选择。缺省生成字段表示继承，不以展示值自动补齐持久化数据。

同一模型与引擎可以保存多份实例配置。各实例独立保存草稿选择和生成默认值，不增加全局草稿选择，也不把实例生成默认值写成引擎全局设置。已有实例快照不随后续引擎默认启动配置的修改而变化。

切换模型或引擎时，按组合分别暂存编辑草稿。不同引擎之间不自动转换 CLI。保存只保存当前组合，取消不写入配置。

旧 assembly 或 CLI 绑定只作为修复线索。用户须重新选择本地来源或明确关闭，才能形成新的显式选择。旧线索不能自动成为已确认来源，本次不增加历史配置自动迁移或备份恢复系统。

### 生效时机与公开请求

加载、上下文、内存、缓存及草稿资源配置在下一次成功启动后生效。保存和预览不准备模型，不启动服务，也不自动重启当前推理实例。

实例生成默认值保存后，从下一次请求生效。每次请求在准入时确定参数快照。后续修改不改变已提交请求，也不改变当前已加载资源的身份。

优先级为单次请求显式值、实例生成默认值、引擎已生效的默认值。待重启的配置和后来修改的引擎默认启动配置，不能冒充当前原生默认值。

公开 JSON 请求、SSE（Server-Sent Events，服务端事件流）和测试场遵循同一规则。省略生成长度上限时，不人为补入 32 或 4096，具体预算由引擎与上下文决定。用户主动发起的短测试可以使用明确展示的单次覆盖值。

GMD 适配引擎字段差异和别名，包括重复惩罚名称、生成长度别名及各自的思考预算语义。停止字符串和结构化对象保留有效内容及附加设置。不支持的字段明确拒绝或显示不适用，不静默丢弃。

### 启动参数文本与软件管理字段

调优项继续遵循文本优先规则。同名表单值保留，界面标示其被覆盖。原始文本不因解析和提示而自动改写。别名、重复选项、多值参数、引号和转义保持原生参数边界。

模型来源、运行身份、监听资源及草稿开关和所选来源属于软件管理范围。冲突文本被剔除并解释实际采用值，不能绕过显式草稿策略或隐式替换资源。最终预览与实际采用的配置一致。

文本语法错误可以保留供修正，启动前要求参数可拆分。能够拆分的未知选项和语义问题继续提示并交给当前引擎判断。文本编辑能力不代替已知参数控件。

### Splash 显式草稿资源

Splash 选择已有原始 safetensors 草稿目录。准备过程检查模型配置、权重或索引、全部分片及张量文件结构，调用所选原生二进制的 model-check 核对配置兼容性。

GMD 在自己管理的不可变 assembly 中引用原始文件，不复制、改写或转换目标与草稿权重。实际张量加载继续由原生引擎验证。文件检查、model-check 和原生加载分别记录。

修改来源后重新准备对应绑定。只加载用户选定来源；缺文件、结构错误、不兼容或原生未实际启用时明确失败，显示所选路径及原因，不扫描安装目录静默改选。

### llama.cpp 草稿模式

llama.cpp 提供本地 GGUF 草稿资源选择。分片模型选择首片，启动前核对全部分片。模式提供普通 draft、EAGLE3、MTP、DFlash 和 DSpark 单选，并依据当前原生版本核对资源要求和支持情况。

常用控件包含最大和最小草稿 token 数、概率阈值和 GPU 层数。设备、线程、K/V 缓存格式及当前版本支持的草稿采样选项放入高级组。空值继承原生默认，调优项继续文本优先。

开启草稿时，仅使用所选来源与单一草稿模式。ngram 配置保留但暂不激活，并说明实际采用值。关闭草稿时，不访问失效的历史草稿资源，允许的 ngram 配置仍可生效。

最终启动参数受控，不能由冲突来源、下载预设或重复模式绕过选择。主模型 Ready 不足以证明草稿成功；须结合实际命令、身份和原生 slots 推测状态验证启用。不能仅凭文件名带 MTP 就认定存在匹配草稿。

### 模型适用性与可选优化

Kev、InnerJev、D3 等不支持草稿的决策路径，显示限制并拒绝不适用的草稿配置。不能仅按层数、隐藏维度或词表尺寸附加 Qwen 草稿。原生后端必须使用草稿时，明确说明关闭后的启动限制。

Splash 草稿执行长度遵循实际引擎的编译约定，不新增其 CLI 未提供的通用运行时长度选项。

compact draft head 默认关闭。启用时，通过控件选择本地 ranking 文件和容量，并检查 SPLCHD02 格式、精确大小、词表匹配与完整排列。容量按当前原生规则检查，为 512～98,304，且是 256 的倍数。

请求开启、预检查通过、原生验证和实际运行分别表达。正常完整 head 回退显示实际原因，不能与草稿加载失败混为一谈。关闭草稿时，保留 compact 设置但不加载或应用其草稿资源。

fast-topk 属于通用目标采样优化。界面按当前原生要求说明 Top K 和 Min P 等生效条件，不把它当成草稿专用参数。

### 实际状态、资源与认证

运行观察属于对应的推理实例。界面分别展示请求开关、检查阶段、所选来源、模式、当前实际来源、原生启用状态和失败原因。不能用另一实例或待启动配置的缓存冒充当前运行状态。

保存新来源或关闭下一次启动的草稿，不改写当前运行所持有的资源。目录失效、解除读取关联和重新绑定继续遵循已有生命周期约定，保留可观察的实际运行与停止入口。

目标和草稿全部分片共用既有在用保护。准备、启动、失败、取消、停止和退出均释放本应用拥有的资源，保留共享模型文件和其他服务。

普通启动只检查健康、加载、身份及所需的草稿实际状态，不隐式发起额外生成探测。短生成由用户主动测试或受控验收明确发起。

API（Application Programming Interface，应用程序编程接口）认证须随配置生效。启用当前引擎支持的 API key 后，内部身份、状态、模型发现、监控、JSON、SSE 及相关推理请求使用对应运行实例的有效认证配置。文本与表单优先级一致，待启动凭据变更不污染当前运行实例。错误、日志与默认调试证据遵循现有凭据脱敏规则。

## 测试决策

### 已确认接缝

沿用项目已经由用户确认的测试边界，不新增测试专用业务入口。主接缝是最高层公开应用业务入口，经既有共用业务控制完成操作。GUI、HTTP、已有 MCP（Model Context Protocol，模型上下文协议）和 SDK（Software Development Kit，软件开发工具包）入口按其现有能力复用这些业务控制。

可控替身仅放在已有外部 I/O（Input/Output，输入输出）边界，包括原生进程和 HTTP、网络、SDK socket 及原生窗口。测试不访问私有方法，不逐行复刻实现，也不建立第二套模型管理或运行状态来源。

通过输入、输出、保存结果、实际发送的参数、实例状态、在用文件和资源收尾验证行为。协议适配通过真实公开请求与响应验证。外部 I/O 替身成功不代替真实引擎和桌面窗口联调。

### 原生验收与结项

按项目固定 macOS arm64 宿主工具链执行格式、静态分析、完整业务和 widget 测试、真实 Mac 构建，并核验交付内容的 Mach-O 架构。保留命令、源码与环境身份、退出码及标准完成报告。

在独立且受控的新应用窗口，实际操作文件/目录选择、取消、A 方案编辑、保存恢复和错误状态。深浅主题、100% 和 150% 文字大小及最小桌面窗口均须可操作。

用已有两份原始 Splash 草稿及其目标模型，分别验证文件、配置、实际张量加载、草稿真实启用和短 JSON/SSE 生成。为 llama.cpp 确定真实兼容的 GGUF 资源与模式，核对实际 slots；逐项列明未实测模式和资源限制。

compact 使用真实匹配 ranking 完成原生加载、实际使用条件及正常回退验收。普通格式正确的合成测试文件，不能证明实际 compact head 兼容。

真实模型、文件检查、原生配置检查、替身回归和桌面窗口分别记录。缺资源或未覆盖的验收项保持开放；不得以测试数量、文件检查或旧候选结果代替最终功能验收。范围调整须由维护者明确接受。
