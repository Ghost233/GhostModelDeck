# 引擎与测试场分区、原题基准评测规格

日期：2026-10-09（Asia/Shanghai）。状态：Q1–Q20 已逐项确定；用户明确调用 to-spec 整理并发布规格，待实施，未运行模型或完成验收。来源决策见 [讨论记录](playground-and-benchmarks.md)，领域词汇见 [CONTEXT.md](../../CONTEXT.md)。

规范工单：[引擎与测试场分区、原题基准评测规格](https://github.com/Ghost233/GhostModelDeck/issues/62)。已由 Ghost233 发布，分类标签为 `ready-for-agent`。

## 问题陈述

作为 Ghost Model Deck 使用者，我目前需要在模型管理、委员会咨询和独立 JEV 测试页面之间切换，才能检查模型运行和推理输出。管理与测试没有清楚分区，通用 LLM 缺少基础请求编辑器，已有 JEV 测试的一部分操作也不完全等价于普通外部客户端。

我希望以统一、可复现的原题基准比较原生 JEV 单模型以及 quick、hard 等命名委员会，知道每种配置的决策效果、端到端延迟和失败表现。现有少量合成案例、合法概率及 Ready 状态无法替代完整任务评测；缺少持久记录，也难以比较版本变化或追溯某一批结果。

## 解决方案

应用顶层提供「引擎」「测试场」两个大 Tab，再显示各区域左侧菜单。引擎区域集中管理模型、引擎、委员会配置和服务；测试场按「通用 LLM」「JEV」设置二级大 Tab，把所有手动基础推理测试集中起来。

通用 LLM 首版提供基础请求编辑器、普通 HTTP 和 SSE；JEV 提供基础测试及五项完整基准：DecideBench、JEVal、一致性 JevBench、JevAdvBench、Jevman。基础测试及基准都模拟普通用户，经实际公开 HTTP/MCP 入口完成模型发现、请求、响应及取消，只使用已 Ready 的对象。

通过 submodule 锁定上游原题和评分版本，保留原始语言、内容及标签，不翻译或改写。安装版首次下载受支持的固定题源和游戏运行时。基准在应用内执行，支持单模型/委员会和 HTTP/MCP 分别比较，保存历史结果、错误与配置，并提供 Jevman 实时观看和逐局回放。只提供完整评测，Jevman 默认 100 局。

## 实现决策

1. **导航与迁移**：顶层为引擎/测试场，再显示对应左侧菜单。引擎保留发现模型、模型库、下载任务、引擎管理、委员会配置和 MCP；设置为公共入口。委员会输入与咨询迁到测试场，现有 JEV 测试场合并到 JEV 基础测试。模型自动能力探测继续属于引擎生命周期。
2. **能力分类**：测试场二级大 Tab 为通用 LLM/JEV；通用 LLM 仅基础测试，JEV 为基础测试/基准评测。未来有实际新能力再增分类，不预建空入口。
3. **基础编辑器**：提供表单/完整 JSON、实际请求预览、返回原文、解析结果、错误、公开 debug、复制和导出；切换不静默删除合法输入。简化表单无法表达的内容保留 JSON 编辑。基础输入输出仅在当前应用会话留存。
4. **通用 LLM**：首版经真实 HTTP Chat，覆盖当前公开支持的文本 messages、参数、普通 JSON/SSE及取消；显示真实文本、用量、结束/中断。本期不新增 LLM MCP、LLM基准或持久多轮聊天历史。
5. **JEV**：保留三题型、复杂 JSON、批量问题、原生调用名与命名委员会选择。原生模型仍是公开可选择对象，移除的是测试客户端直调内部推理的通道。
6. **真实公开调用**：模型发现使用实际 HTTP模型列表或MCP发现工具；推理经公开HTTP或MCP工具，服务端沿用既有生产控制及受管实例。不得直接调用内部推理控制器，不使用进程内请求lease、特殊登记header或其他测试专属取消特权。取消遵循普通HTTP连接或标准MCP会话能力，不影响无关客户端请求。
7. **可用性与通道**：只使用已Ready且经所选公开入口可调用的对象；不可用显示原因，不启动或加载模型。JEV默认HTTP，可选MCP或两通道分别评测，结果和耗时分开记录。内部配置元数据可用于记录/锁定，不能代替真实请求或输出证据。
8. **五项完整基准**：DecideBench、JEVal、一致性JevBench、JevAdvBench、Jevman全部实施。只采用来源发布的原题、标签和原评分，保留原始语言，不翻译、改写、缩写或补造。必要协议映射不改变任务、候选及评分；超出模型能力的原题按真实错误记录，不截断后伪装完成。
9. **原题版本**：题源以submodule固定完整提交；代码仓库与实际数据仓库分别核实，取得真实Parquet/JSONL/压缩请求等内容，不能把大文件指针当题集。固定套件身份、内容摘要、题目/请求组数量和评分版本。
10. **完整规模**：不提供快速试跑、自选题量或自造子集模式。执行固定完整套件；Jevman默认100局，沿用原游戏规则、指令、动态路线特征和逐帧录像。取消或故障中断的记录明确不完整。
11. **请求结构与计分**：保留DecideBench成对题、一致性套件请求组/关系、JevAdvBench原题/扰动/重复控制及Jevman游戏调度；不全部拆为独立单题，不将协议拒绝当成模型抗扰动成功。忠实实现公开原计分并记录版本。
12. **资源获取**：安装版首次下载受支持的固定题源并缓存，展示来源、版本、准备进度和失败；不要求Git。应用下载管理固定游戏运行时，不依赖预装Node。准备完成后才评测，资源下载/安装不计入模型推理延迟。
13. **更新与来源条件**：开发侧更新submodule并验证数据、格式、标签与评分适配，随应用发布支持版本；安装版不追踪上游最新分支，在途批次不换题库，旧版保留历史引用。核实各源获取条件、数据/代码许可与署名，首次下载不免除原来源条件。
14. **执行顺序**：一批可选多个原生模型、委员会和基准，按对象、基准、通道依次执行；保留套件内部原请求组和游戏调度，避免不同对象并行争用同一机器资源。
15. **身份与锁定**：批次记录题集/评分版本、通道、模型资产、引擎、量化、实际运行配置、委员会成员和超时。运行中禁止编辑/删除/重命名参赛委员会和公开调用名，取消或结束后释放锁。手动停模型仍允许；代次/外部配置变化不得静默混入同一对象成绩，未知成功席位覆盖不得伪造。
16. **期限**：客户端超时可设置并记录，基础LLM默认120秒、普通JEV默认30秒、Jevman沿用2秒决策时限。服务端原配置继续生效，不自动修改模型/委员会预算。
17. **失败与取消**：单题超时、非法响应等按原评分记录后继续，不自动重试、不补造概率。目标失去可调用状态时停止该对象，其他对象继续；资源缺失或整套格式错误明确为准备失败，不静默丢题。取消结束整批，停止新请求、以公开协议结束在途请求并封存晚到结果。
18. **生命周期**：基础测试离页取消，保留输入与已有输出；基准切Tab、离页、关窗继续，返回可查看进度和取消。明确退出时停止并保存中断，重启仅查看历史，不自动续跑。基准任务及持久记录由应用拥有，页面只观察和操作。
19. **报告**：各基准保留原评分并独立报告，不合成跨基准总分；委员会与同批单模型比较，HTTP/MCP分开统计。版本、配置或通道不同的历史不得混算回归差值。
20. **公共指标与概率**：报告规模、完成及有效返回、失败/超时和端到端延迟分布；失败不从覆盖统计消失，超时不作为成功耗时。原评分之外的统计另标辅助指标；适用标签及分布才评概率质量，注明标签来源。原生confidence不当成正确率，一致性/抗扰动/准确率分别表达。
21. **证据与诊断**：保存实际输入、公开响应/错误、时序及版本身份；沿用既有凭据脱敏，不保存认证凭据。诊断只用公开debug，默认性能轮与诊断轮区分，另一轮席位信息不能冒充当前请求证据。
22. **持久记录**：本地保存批次摘要、逐题/逐组结果、配置和状态，支持重启查看、导出与删除；完成、失败、取消、中断分别标识。删除不得损坏模型、题库、其他批次或共享资源。
23. **游戏观看与回放**：Jevman支持实际游戏实时观看、逐局成绩、录像回放及独立重放核对；回退与延迟单列，greedy代走不得冒充模型回答。精确回放使用已记录轨迹，不能称为重新推理复现同一局。
24. **共用运行图**：导航、编辑器、资源准备、批次控制、报告及游戏桥接复用同一生产实例/公开入口，不新增第二套模型管理、委员会算法或测试专属业务入口。具体资源格式和依赖版本由实施者按固定来源核实，不据此降低五项范围。

## 测试决策

测试接缝已在Q7、Q9与后续确认中由用户明确：模拟普通用户，使用实际HTTP/MCP公开发现、请求及取消，禁止内部推理捷径和取消特权。沿用现有应用级测试场入口与公开客户端作为最高层级接缝；基准扩展同一级批次入口。验证可观察的输入输出、网络交互、状态、记录及资源变化，不调用私有方法、不逐行复刻内部逻辑、不增加测试专用业务API。

可借鉴现有公开网关、MCP、测试场、委员会三题型/聚合、模型注册表生命周期及应用退出收尾测试。可控替身仅放在外部引擎/下载网络、进程、文件和必要平台I/O边界；真实公开HTTP/MCP外壳及生产业务保持真实。受控小型数据可用于评分和流程断言，但不能作为产品快速模式或完整真实评测证据。
