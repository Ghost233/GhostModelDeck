# 引擎与测试场分区、原题基准接入

日期：2026-10-09（Asia/Shanghai）。状态：Q1–Q20 已确定，设计前沿为空；用户明确调用 to-spec 整理并发布正式规格，尚未开始实施。通过 grill-with-docs 的 grilling / domain-modeling 工作流逐轮记录。正式规格与验收见 [规格正文](playground-and-benchmarks-spec.md)，领域词汇见 [CONTEXT.md](../../CONTEXT.md)。

规范工单：[引擎与测试场分区、原题基准评测规格](https://github.com/Ghost233/GhostModelDeck/issues/62)，分类标签 `ready-for-agent`。

## 已确定的方向

- 界面顶层提供两个大 Tab：「引擎」和「测试场」，先选择顶层区域，再显示该区域的左侧抽屉菜单。引擎区域保留发现模型、模型库、下载任务、引擎管理、委员会配置、MCP；设置为两个区域都可访问的公共入口。
- 用户手动发起的基础推理测试集中到测试场：委员会输入与咨询迁入，既有 JEV 测试场归入 JEV 基础测试，新增通用 LLM 基础请求编辑器。模型加载和能力准入的自动检查与手动测试区分，不由页面迁移隐式改变。
- 测试场按模型能力设置二级大 Tab：首期为「通用 LLM」与「JEV」，未来有实际新能力再增加分类，不预建空分类。
- 先选择能力分类，再进入其左侧菜单：通用 LLM 仅「基础测试」；JEV 提供「基础测试」「基准评测」。委员会页只保留配置管理，现有输入与咨询操作迁到测试场。
- 基准在应用内完成：选择基准与模型/委员会、启动执行、查看进度、取消任务及查看结果，不将首版限制为仓库命令行入口。
- 通用 LLM 首版提供基础推理测试，包括输入、输出、流式显示和取消；JEV 首版提供基础推理测试与基准评测。通用 LLM 基准留待后续，不在本期设置空基准入口。
- 原生 JEV 单模型及 quick、hard 等命名委员会均可作为基准评测对象；名称不自动代表速度、难度或质量等级。
- 测试场只使用已 Ready 且能经所选公开入口调用的对象，展示不可用原因，不代用户启动或加载模型。
- **基础测试和基准必须模拟正常用户请求，经实际 HTTP 或 MCP 执行。** 测试客户端不得直接调用内部推理入口，也不得通过仅进程内可取得的请求 lease 或特殊登记 header 获取取消特权。模型发现与选择基于所选公开入口，取消遵循正常客户端的协议能力。内部配置元数据的记录不替代真实请求或返回证据。
- 五项首批基准全部接入：DecideBench、JEVal、一致性 JevBench、JevAdvBench、Jevman；各自保留上游请求组织、原始题目及评分规则。
- 添加通过 submodule 引入的上游题源，固定版本。只采用来源发布的原始题目，保留内容和标签，不由代理翻译、改写或补造；不限制题目语言。
- 同一轮比较使用同一题集和评分规则。来源、题目版本、模型及委员会配置与结果关联，题集更新不覆盖旧结果或混称为同一批评测。
- 本地持久保存每批摘要、逐题结果、题库版本与实际配置，支持重启后查看、导出及删除；基础测试的输入输出仅在当前应用会话保留，可复制/导出。
- 通用 LLM 本期使用已有 HTTP JSON/SSE，不新增 LLM MCP 工具。JEV 默认 HTTP，可以选择 MCP，也提供两通道分别评测；结果与指标按通道独立记录。
- 基础测试离页取消，保留输入和已有输出；基准切换 Tab、离页或关闭窗口后继续执行，允许返回查看与取消。明确退出时停止并保存部分结果，标记中断；重启仅展示历史，不自动续跑。
- 安装版首次使用时下载固定版本题源并缓存，展示来源与版本；下载完成后才开始评测。开发仓库通过 submodule 锁定题源，安装版不要求用户安装 Git。题源更新单独处理，不在正在运行的批次内改变版本。
- 应用下载并管理固定版本的 Jevman 游戏运行时，展示准备状态，不要求用户自行安装 Node。资源准备与模型推理评测分别计时，游戏决策仍走实际 HTTP/MCP。
- 基础测试采用表单与完整 JSON 请求编辑器，展示实际请求、返回原文和解析结果；LLM 支持流式显示，JEV 保留三题型和批量请求。
- **只保留完整评测，不提供快速试跑或自选题量模式。** 每个基准使用固定的完整套件，Jevman 默认 100 局，取消后的部分结果不能称为完整评测。
- 一个批次可选择多个对象和基准，按对象、基准、通道依次执行；套件内部保留上游请求组和游戏调度，不将其拆为独立单题。
- 客户端超时可设置并记录：基础 LLM 默认 120 秒、普通 JEV 默认 30 秒、Jevman 沿用 2 秒决策时限。不修改模型/委员会自身服务端配置；单题失败记录后继续，目标失效停止该对象、其他对象继续，取消结束整批，失败不自动重试。
- 各基准按原始评分规则报告，并附端到端延迟、有效返回率、超时和失败；有适用标签及概率分布时提供概率质量指标。委员会与同批单模型比较，按基准与通道分别报告，不合成跨基准总分。
- 开发侧更新 submodule、验证原题与评分适配后，通过应用发布受支持的固定题库版本；安装版不自动追踪上游最新提交。旧版本仍可供历史引用。
- Jevman 提供实际游戏的实时观看与历史逐局录像回放，保存逐局成绩和重放核对结果。
- 批次运行期间禁止编辑、删除或重命名正在参赛的委员会及公开调用名，取消后可修改；模型仍可手动停止，按目标失效处理，不将不同配置混入同一结果。

## 与已有规格的关系

[原测试场规格](protocol-converters-and-playground.md)及 [ADR 0001](../adr/0001-virtual-jev-protocol-boundary.md)曾将当期测试场专项验收限定为 JEV，并允许原生内部测试通道。本次用户明确增加通用 LLM 基础推理分类，且要求测试全部经过真实公开入口，是新的后续范围，不把旧范围记录改写成已经交付。原生模型仍可作为通过公开入口选择的对象；移除的是测试客户端直调内部接口的通道。命名委员会路由、实例复用及标准 JEV 输出语义继续以既有契约为基础。新公开调用边界见 [ADR 0005](../adr/0005-real-client-evaluation-boundary.md)。

Q1–Q3 已确认：顶层引擎/测试场后再进入左侧抽屉菜单；基准在应用内完整执行；通用 LLM 首版基础推理与流式/取消，JEV 首版基础测试和基准。尚未整体确认或开始实施。

Q4–Q8 已确认：管理菜单归引擎区域；按能力选择左侧基础/基准菜单；五项基准全部接入；仅 Ready 对象且全部模拟真实 HTTP/MCP 客户端；基准结果本地持久保存并可查看/导出/删除。

Q9–Q12 已确认：JEV 默认 HTTP，可选 MCP 或两通道分别评测；基础离页取消、基准跨页/关窗继续，明确退出保存中断且不自动续跑；安装版首次下载固定题源并缓存；应用下载并管理固定游戏运行时。批次生命周期另见 [ADR 0006](../adr/0006-evaluation-run-lifecycle.md)。

Q13–Q20 已确认：基础请求编辑器与会话留存；仅完整评测，Jevman 默认 100 局；对象/基准/通道顺序执行；客户端期限与失败规则；原始分基准评分和公共性能指标；随应用发布受支持题库版本；游戏实时观看/逐局回放；运行期间锁定参赛配置。Q14 的「不提供」已通过追加澄清明确为只保留完整评测。

原题来源与固定版本的决定已记录在 [ADR 0004](../adr/0004-original-benchmark-sources.md)。讨论开始时左侧导航包含发现模型、模型库、下载任务、委员会、推理测试场、MCP、引擎管理和设置；现有手动推理入口为委员会咨询与 JEV 测试场。通用 LLM 尚无手动 prompt 输入界面，已确定新增基础请求编辑器，不能称为现有界面的搬迁。引擎启动时的文本/typed 探测属于 Ready 准入证据，与用户手动基础测试分别表达。

## 题源接入事实

2026-10-09 补充核对上游 README 与目录，未克隆或运行题源：

| 来源 | 已核实的数据形态与接入差异 |
|---|---|
| [DecideBench](https://github.com/choyiny/decidebench/tree/18e9c5eedd2855257ae534b5879ebba613479586/data/v1) | 原题为仓库内 JSONL，可直接读取；上游脚本用 Python，应用可忠实实现原计分规则 |
| [JEVal](https://huggingface.co/datasets/carlosxiang/JEVal/blob/main/README.md) | 原题在 HF 数据仓库 `data/test.parquet`，GitHub 模型代码不能替代题库；需取得真实 Parquet 并解析或构建时无损转换 |
| [一致性 JevBench](https://github.com/JevBench/jevbench) | 仓库带冻结 `tests.jsonl.gz`；需保留请求组与关系评分，不能拆成互不相关的单题 |
| [JevAdvBench](https://github.com/JevAdvBench/JevAdvBench#data) | 仓库带原题与扰动 JSON，可直接采用发布变体；原题重复控制与成对评分需保留 |
| [Jevman](https://github.com/opper-ai/jevman-benchmark#scripts) | 动态游戏任务，上游依赖 Node/TypeScript；静态游戏记录不能替代新模型实际参赛 |

JEVal 数据卡尚未整合第三方来源的统一许可；JevAdvBench 数据许可为 CC BY-NC 4.0、代码 MIT，供应商原场景另有条款。题源可获取与可随应用分发是分别核对的事实；已确定五项均接入、安装版首次下载固定题源，实施时核实各来源具体获取条件。游戏运行时、静态套件评分适配与题集版本纳入正式验收。

## 公开调用与生命周期事实

- 通用 LLM 当前公开入口是 HTTP `POST /v1/chat/completions`，支持 JSON/SSE；当前 MCP 仅提供 `decide_jev`、`decide_jev_batch`、`list_jev_models`，没有通用 LLM 工具。已确定本期不增加 LLM MCP。
- HTTP 模型发现使用 `GET /v1/models`，MCP 使用 `list_jev_models`；两项服务当前由应用启动自动启动，MCP 页另有启停入口。公开模型路由启用与模型 Ready 分别检查。
- 现有 JEV 测试场 HTTP 成功链路经过真实网络，但请求取消使用内部 `PublicJevRequestLease` 和 `x-gmd-owned-jev-request`；这与新确认的普通客户端边界不符，需要替换。普通 HTTP 客户端的断连取消时效须实际验证，不能从源码回调直接宣称成功。
- 当前关闭窗口不退出应用，公开服务保留；明确退出应用会取消请求并收尾资源。新基准任务已选定跨页面/关窗继续、退出保存中断，具体资源收尾和记录验收仍需实现。
