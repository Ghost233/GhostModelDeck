## 已确认的共同理解摘要

### 场景名称与统一模型名字

- 默认以短／长上下文和非视觉／视觉组成四类场景，支持关闭场景，例如同时关闭两类视觉场景。
- “视觉”只属于用户定义的场景说明，不与实际业务或模型能力判断关联。用户选择绑定后按该绑定调用，不检测、筛选或验证其视觉能力，也不由场景文字触发特殊路由或成员处理。
- 暂时固定四个场景槽位，不提供新增或删除；场景显示名称、模型名字、绑定和启用状态可编辑。固定数量用于保持给 LLM 的 MCP 提示词结构稳定。
- 首次预建并启用四个场景，默认显示名称为短上下文、长上下文、短上下文＋视觉、长上下文＋视觉，均可修改。模型名字与后台绑定由用户自行配置；未配置或没有可用运行实例时不出现在 MCP 列表中。
- 上下文由绑定实例决定，不再固定为 4096 或 32768。
- 上下文以实例已生效的启动配置为准，无需读取进程观测值，也不要求实例先启动一次才能确定初始容量。单实例取自身容量；委员会取全部成员已生效配置值的最小值，不随成员启停变化。
- 场景显示名称与模型名字是两个独立字段。例如场景显示“4k上线+视觉”，模型名字为 `fast-v`，后台再绑定实际实例或委员会。
- HTTP 与 MCP 都使用统一的模型名字，即请求中的 `model`。既可使用实际实例的模型名字，也可使用委员会或场景定义的虚拟模型名字；不建立按传输方式区分的命名规则。
- MCP 默认发现列表仍只列出四个场景中已启用且可用的模型。发现列表的展示范围与已知模型名字的直接调用分别表达；不因实际模型未列入默认 MCP 列表而禁止按名字调用，调用仍遵循相应入口的能力与可用性要求。
- HTTP 的 `/v1/models` 列出全部可用模型，包括实际实例、委员会及场景定义的虚拟模型。
- 绑定必须落到已保存实例。未启动的实例不出现在 MCP 返回列表中，不能把模型文件、已关联引擎或已保存配置当作已运行。
- MCP 服务器说明和工具描述采用固定模板，按当前场景配置生成调用名、用途及上下文。客户端重连或刷新工具时取得最新说明，动态可用性以模型发现列表为准。
- 实例参数编辑窗口即时预览该实例、关联委员会及 MCP 场景的“原容量 → 新容量”；保存后保留待应用配置，取消不保存，不自动重启实例。运行中的实例重启后新参数才生效，并更新关联委员会与场景的有效容量。

### 表格管理

- 模型、引擎和实例统一采用表格展示，替换不清晰的卡片堆叠。
- 模型表每个模型变体一行；引擎表每份安装或关联条目一行，未安装的默认引擎保留条目；实例表每份保存的“模型＋引擎＋参数”配置一行。
- 同一模型的不同实例独立成行，各自展示参数、运行状态和操作。
- 保留已确认的摘要、分批加载和展示原则，不一次性展示全部原始数据。
- 模型表默认列：模型名、格式、量化、大小、所在目录、操作。
- 引擎表默认列：引擎名、仓库或本地路径、版本、状态、操作。
- 实例表默认列：实例名称、模型名字、对应模型、引擎、上下文、并发、自启动、状态、操作。
- 常用操作放行内，其余放“更多”；提供搜索、状态筛选、表头排序和分页加载。窗口宽度不足时横向滚动。

### 两行运行进度

- 参考图中的紧凑运行状态；每个运行实例独立显示两行。
- 上行显示并发格子、prefill／decode 阶段及处理数量；下行显示模型名字、引擎及运行摘要。
- 同一模型运行两个实例时显示两组进度；场景或委员会请求计入实际执行的底层实例，不重复统计并发。
- 上方格子表达并发数量，四个格子表示四个并发。
- 显示当前 prefill／decode 阶段及各自已经执行的数量。
- 格子代表实例的推理执行槽位，显示空闲、prefill 或 decode 及当前请求的处理数量；请求完成后槽位供后续请求复用。
- 排队请求单独显示数量，不占额外格子。例如 4 个执行、3 个排队，显示 4 个执行格子及“排队 3”。
- 推理并发槽位与 HTTP 接收容量分开，不能用后者冒充推理并发。
- 只展示已知监控数据。阶段未知显示“运行中”；未提供的 token 数或速度显示“—”，不伪造为 0。
- prefill 总量已知时显示已处理／总量，否则只显示已知处理量；decode 显示已生成数量，不估算完成百分比。缺少监控数据不影响实例启动或正常调用。
- 第二行显示模型名字、引擎、本次运行累计输入／输出 token，以及最近 1 分钟的平均 prefill／decode 速度。
- 速度采用最近 60 秒的滚动平均，不混用其他实例或上一次运行的数据。实例重启后重新统计。
- 去掉运行监控的速度曲线与详情入口，保持每实例两行，不保留展开详情。

### 启动自动加载

- 设置页保存两个独立配置：是否随 GMD 启动自动开启总开关，以及哪些实例自启动。
- GMD 启动时按“总开关自启动”设置决定是否开启总开关；开启后再启动已勾选自启动的实例。不根据上一次运行时的总开关状态恢复。
- 打开引擎总开关时，只自动启动设置了自启动的实例；未设置的实例仍由用户手动启动。
- 全新安装默认不自启动总开关，新建实例默认不勾选自启动；已有保存的选择保留。
- 所选实例并发启动，独立显示状态与结果；已经运行或正在启动的实例跳过重复启动。
- 某个实例失败只记录该实例的错误，其他实例继续启动；由用户手动重试，不自动换模型或反复重试。
- 已有启动集合的存储接线在实施时复用，不能另外维护互相冲突的自启动列表。

### 引擎总开关

- 引擎区增加统一总开关。关闭时不允许启动任何引擎，开启后才允许启动。
- 关闭总开关时停止全部由 GMD 管理的运行实例，不能仅禁止新的启动。
- 打开总开关时，按实例的自启动设置自动启动；未设置自启动的实例保持手动启动。
- 关闭时立即拒绝新请求，取消正在执行、排队、启动中和测试运行中的任务，停止全部受管实例并释放资源，不等待推理完成。
- 客户端收到明确的取消或服务关闭结果；GMD 窗口及 HTTP／MCP 接入保持运行。
- 总开关的当前开关状态不持久保存。持久保存的是“总开关是否自启动”和实例自启动列表；手动打开或关闭总开关不改变这两项设置。
- 自动加载不能绕过关闭状态。总开关自启动默认关闭。

## 当前实现事实

- MCP 当前暴露 `decide_jev`、`decide_jev_batch` 和 `list_jev_models`，用途是结构化 JEV 判断。
- 当前 JEV 输入仅接受 `images` 为 null 或空数组。Q15 明确“视觉”只是场景定义，不能据此推导必须新增图片协议、能力检测或视觉专用流程。
- 实例配置与实际运行状态已分开。委员会引用实例，保留已有部分成员成功的 partial 规则，不增加按“视觉”场景判断成员能力的分支。
- 已有 `StartupModelSet` 保存实例选择并用于启动服务；设置页尚无本次要求的自动加载配置。
- 已有监控数据包括阶段、token 数、速度、运行及排队数。Splash 当前 capacity 取自 HTTP 请求容量；Q18 已明确格子必须对应推理执行槽位，实施时需据此修正接线。
- 现有运行监控已展示累计 token、平均 prefill／decode 速度及最近 120 个采样点的速度曲线。Q20 要求移除曲线与详情，速度改为最近 1 分钟的滚动平均。
- 当前已有退出／回收用的启动准入控制，尚无本轮要求的用户总开关及独立的总开关自启动设置。
- 现有调用入口会在实例不可用时明确报错，不隐式启动模型；本轮尚未提出改变这项行为。

## 讨论树与顺序

1. MCP 用途与输入输出范围。
   - 确认后讨论场景名称、统一模型名字、上下文及场景文字与业务的边界。
   - 再讨论实例／委员会绑定、运行可用性和发现／调用一致性。
2. 表格结构与按实例组织运行行。
   - 确认后讨论列、操作、分页和两行监控。
3. 并发格子与指标语义。
   - 确认后讨论请求分配、排队、刷新和引擎缺失数据。
4. 引擎总开关。
   - 先确认已有实例、在途请求和启动中的行为，为自动加载提供前置条件。
5. 自动加载实例。
   - 在总开关规则明确后讨论触发时机、失败和资源不足。

## 已确认的访谈结论

- Q1：用户同意四类 MCP 场景统一用于结构化判断，保留 choice／score／noul 的结果形式。
- Q1 中将“视觉场景”解释为必须新增图片输入与推理接线的内容，经 Q15 修正：场景文字仅作定义，不据此增加业务接线或能力判断。
- 普通聊天与开放式视觉问答仍通过 HTTP／测试场使用，本轮不新增这类 MCP 工具。
- Q2：用户保留委员会的现有可用性规则：至少一个成员实例可用，启用的场景别名即可出现在 MCP 模型列表中，不要求所有成员均就绪。没有可用成员时不返回。
- Q3：用户要求场景及名称可编辑，不采用固定的四个调用名。上下文由绑定实例决定：单实例取自身容量，委员会取成员中的最小值。
- 先前的 4096／32768 固定上下文方案作废。short／long／short-vision／long-vision 仅为未获采纳的命名建议，不作为实现约束。
- Q4（经 Q6 澄清）：上下文取实例配置中确定的实际容量，不取模型文件声明的理论上限。例如模型声明 128K、实例配置为 8192，则对外显示 8192；成员配置为 8192 与 32768 的委员会显示 8192。
- Q5：用户要求委员会容量按全部成员取最小值，委员会确定后容量固定，不因成员启停而变化。未启动成员同样计入；不采用仅就绪成员参与并动态调整容量的建议。
- 委员会可见性与容量分开：至少一名成员可用即可被发现，但对外容量仍是全部成员的固定最小值。
- Q6：用户明确容量由实例配置确定。无需成员先启动一次，不采用“未启动过所以容量未知、等待全部成员加载后再固定”的建议；此澄清取代 Q4 中被误解为运行后观测的说法。
- Q7：用户要求暂时固定四个场景槽位，用于稳定 MCP 提示词给 LLM 的使用方式。不新增或删除槽位；保留 Q3 的可改名和配置能力，以及关闭场景的能力。
- Q8：用户同意 MCP 提示词按固定模板结合当前场景配置自动生成，无需另行手改。客户端重新连接或刷新工具后取得最新说明，当前可调用对象仍以发现列表为准。
- Q9（生效时机由 Q11 修正）：用户同意自动重算引用成员实例的委员会与 MCP 场景容量；仍按全部配置成员取最小值，不随实例启停变化，不自动重启实例。
- Q10（生效时机由 Q11 修正）：用户同意在实例参数编辑窗口即时预览该实例、关联委员会及 MCP 场景的容量变化，展示“原容量 → 新容量”；取消不保存。
- Q11：用户明确新参数在重启实例后才生效。保存只更新待应用配置与预览，不立即改变运行中实例及关联委员会、场景的有效容量；实例重启应用新参数后再同步更新。该结论取代 Q9、Q10 中“保存后立即生效”的表述。
- Q12：用户要求场景显示名称与 MCP 模型调用名分开。例如显示名称可以为“4k上线+视觉”，调用名为 `fast-v`；调用名再绑定后台实例或委员会。用户本轮未确认原 Q12 中对直接使用后台名称的限制及 HTTP 影响。
- Q13：用户明确 HTTP 也使用模型名字，一切都用模型名字，无论实际模型还是用户定义的虚拟模型。撤回“仅 MCP 使用场景调用名、HTTP 使用另一套公开名”及“MCP 禁止实际模型名字”的建议。Q12 中的调用名统一称为模型名字；场景显示名称继续与模型名字分开。
- Q14：用户同意 HTTP `/v1/models` 列出全部可用的实际实例、委员会及场景虚拟模型；MCP 默认列表只列四个场景中已启用且可用的模型。两种入口均可按有效模型名字直接调用。
- Q15：用户明确不考虑“部分成员不支持视觉”的场景专用逻辑。“视觉”仅为场景定义，没有实际业务关联；用户选择的模型默认按其选择使用，不做视觉支持判断。撤回上一轮新增视觉能力分支的建议；现有通用调用失败与委员会处理规则继续保留，实际失败如实返回。
- Q16：用户同意三张表的行单位：模型变体、具体引擎安装／关联条目、保存的实例配置。未安装的默认引擎保留条目；同一模型的多个实例分别展示参数、运行状态和操作。
- Q17：用户同意每个运行实例独立展示两行进度，上行为并发格子、阶段与处理数量，下行为模型名字、引擎与运行摘要。同一模型的多个实例分别展示；虚拟模型请求归入实际执行的底层实例，不重复计算并发。
- Q18：用户同意并发格子代表推理执行槽位，排队请求独立计数，不增加格子。格子展示空闲、prefill 或 decode 及对应处理数量，请求完成后可复用；4 个执行加 3 个等待显示为 4 个执行格子与“排队 3”。
- Q19：用户同意只显示已知监控信息：阶段未知显示“运行中”，未提供的 token 或速度显示“—”，不显示为 0。prefill 总量已知才显示已处理／总量，否则只显示已知处理数量；decode 显示已生成数量，不估算完成百分比。缺少监控数据不影响实例启动和正常调用。
- Q20：用户要求去掉曲线与详情，平均 prefill／decode 速度按最近 1 分钟计算。其余推荐项同意：第二行保留模型名字、引擎和累计输入／输出 token；统计按实例本次运行隔离，重启后重新统计。取消上一轮保留曲线和详情入口的建议。
- Q21：用户要求关闭引擎总开关时全部关闭；打开时只自动启动标记为自启动的实例，未设置的仍手动启动。撤回“关闭只阻止新启动、保留已运行实例”的建议。
- Q22：用户同意关闭总开关时立即取消执行中、排队及启动中的任务，不等待推理完成，停止实例并释放资源。客户端收到明确的取消／服务关闭结果；GMD 窗口及 HTTP／MCP 接入保持运行。
- Q23：用户要求不记录上一次总开关的运行状态，改为分别保存“是否自启动总开关”和“是否自启动实例（列表）”。GMD 启动时依前者决定是否开启总开关，开启后依后者自动启动实例；手动切换总开关不修改自启动设置。撤回恢复上次开关状态的建议。
- Q24：用户同意全新安装默认不自启动总开关，新建实例默认不勾选自启动，由用户自行开启；已有保存的自启动选择保留。
- Q25：用户同意所选实例并发启动，各自显示状态和结果；已运行或启动中的实例跳过重复启动。单个实例失败不阻止其他实例启动，用户手动重试，不自动替换模型或反复重试。
- Q26：用户同意三张表的默认列：模型表为模型名、格式、量化、大小、所在目录、操作；引擎表为引擎名、仓库或本地路径、版本、状态、操作；实例表为实例名称、模型名字、对应模型、引擎、上下文、并发、自启动、状态、操作。常用操作行内展示，其余放“更多”；提供搜索、状态筛选、表头排序和分页加载，宽度不足时横向滚动。
