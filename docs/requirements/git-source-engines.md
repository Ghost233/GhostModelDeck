# 从 Git 源码构建引擎

工单：[从本地 Git 或 GitHub 源码构建并绑定 llama.cpp 引擎（#78）](https://github.com/Ghost233/GhostModelDeck/issues/78)。

2026-10-11，用户要求引擎由指定的本地 Git 仓库或 GitHub 地址获取。应用克隆到本机，编译后登记产物，再供模型选择并运行。引擎版本由用户的仓库与引用决定。

当前实现范围是 llama.cpp 及采用相同 CMake 构建和服务协议的分支。其他引擎仍需各自的构建与运行适配。原有引擎登记、启动参数和运行实例继续保留。

## 用户流程

1. 在引擎管理页选择“从 Git 构建”，填写名称、仓库地址和可选的分支、tag 或 commit。未指定引用时，采用仓库默认分支。
2. 应用一次检查 macOS arm64、Git、CMake 和 Apple 编译工具。CMake 支持已有安装和显式可执行路径；缺少依赖时显示原因。
3. 应用在自己的目录创建独立克隆，展示克隆、配置、编译和核验进度，保留日志及真实退出码。本地源仓库的未提交内容不进入克隆，也不被改动。
4. 编译通过后核验 `llama-server` 与所需库，记录来源、实际完整 commit、构建命令和产物指纹，然后登记为可选择的引擎。
5. 模型运行对话框使用这个登记项，沿用引擎默认参数、模型独立参数和能力探测。真实推理就绪后才向公开客户端提供能力。

## 验收

- GitHub 地址和本地 Git 仓库均完成克隆、编译与登记。分支、tag 和 commit 可选择；错误地址、引用及编译失败有明确结果，失败产物不登记。
- 记录每次构建的实际提交。再次构建生成独立产物，已有运行实例继续使用原产物；应用不自动追踪上游或替换运行中的引擎。
- 用户可取消构建。取消和应用退出释放本应用创建的构建进程，晚到结果不登记，原仓库和其他引擎保留。
- 构建产物与依赖库保持完整，重启后登记项可核验和运行，解除关联保留启动配置。
- 当前固定 Flutter／Dart SDK、lockfile 和 macOS arm64 宿主门禁通过。真实桌面完成 Git 源码构建、选择新引擎加载模型及普通公开 HTTP 调用。

构建方法参考 [llama.cpp 官方说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)。CMake 编译与运行协议是本切片的明确边界，不能凭任意仓库地址宣称所有引擎都已适配。
