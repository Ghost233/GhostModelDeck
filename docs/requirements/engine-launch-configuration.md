## 已确认的共同理解

### 配置与入口

- 引擎管理页为每个登记引擎提供默认参数配置入口；运行模型时可选择继承默认配置或启用模型独立配置。
- 模型独立配置按「模型变体 × 具体引擎登记项」保存，使用与引擎相同的表单、参数文本和最终预览编辑器。
- 首次创建模型独立配置可复制引擎当前整份配置；此后独立保存表单值与参数文本，不按参数差异与引擎默认配置动态合并。
- 切回继承时保留独立配置，方便再次切换；独立配置全部为空与没有模型覆盖分别表达。
- 当前可运行引擎的初始表单沿用现有软件默认值，高级文本初始为空；用户可修改或清空表单项。

### 参数优先级与解析

- 软件管理的模型路径、监听地址/端口、对外模型标识等字段优先于用户配置。文本中出现这些字段时，在生成执行参数时剔除并明确提示最终软件值，原始输入文本仍保留。
- 其他自定义参数中，文本优先于表单。同名或已识别等价别名在两处填写时，以文本为准，对应表单项标红提示「已被文本覆盖」；保留表单值，仍允许启动。
- 原始文本不因解析、识别或提示被自动改写；文本中的参数顺序、重复项与值的边界保留，重复文本参数由引擎解释。
- 结合内置规则和当前引擎版本的帮助信息尽力识别名称、别名与说明，至少识别内置支持的参数；帮助信息不足或读取失败时使用可用规则并说明识别限制。
- 未知参数保留并传给引擎；已知参数的缺值、类型或其他语义问题也仅提示，最终由引擎判断并展示实际启动错误。
- 参数文本只填写参数，支持引号及带空格的值；可执行文件和子命令由软件生成。沿用直接传递参数数组的进程执行方式，不依赖 shell 展开。
- 引号未闭合等使文本无法拆为参数列表时允许保存，但启动前要求修正并指出位置，不能生成虚假的最终命令。

### 预览与生效

- 提供完整启动命令预览和复制，包含可执行文件、软件管理字段及最终自定义参数；启动前动态字段标明启动时分配，启动后保留并展示该次实际使用命令。
- 预览和实际启动使用同一份参数生成结果，防止展示值与实际执行值不一致。
- 保存配置仅影响后续启动，已有运行实例保持原参数；立即应用由用户手动重启模型。已有 SDK、GUI 和公开业务入口共用启动配置。

### 配置保留与范围

- 引擎版本改变后保留原表单与文本，刷新识别并提示版本差异，不自动重写或重置调优值；保留参数不改变原有引擎安装/关联核验要求。
- 解除关联后保留为未关联配置，重新关联时由用户手动选择恢复默认配置及对应模型覆盖，不自动套用到其他登记项。
- 本次实际运行参数应用覆盖当前可运行的 llama.cpp / JEV 路径；oMLX 提供配置保存和识别，维持当前生产运行限制，并明确呈现该限制。
- oMLX 生产运行接通、共享池与每模型参数关系、关联安装运行归属，以及 Splash 运行适配保持后续范围。保存参数不代表未接通的引擎已经可运行。

### 验收要点

- 表单与文本同名参数：文本值实际生效，表单标红且保留原值；删除文本项后可重新使用表单值。
- 未知参数、重复项、引号、带空格值与别名处理按上述规则保真；语义错误仅提示，无法拆分的文本可保存但不能启动。
- 受控字段处理有提示；完整预览与实际进程参数一致，启动后记录的是该次实际值。
- 不同模型变体/引擎配置独立，继承切换、独立空配置、重启应用后的持久化、升级及解除关联后的手动恢复均有证据。
- 真实 llama.cpp / JEV 启动证明参数生效、错误如实呈现、已有实例不被保存操作重启；oMLX 的配置能力不被误报为生产运行能力。

## 当前事实

- 关联引擎保存路径、实际版本和内容指纹；没有持久保存自定义参数。
- llama.cpp 启动参数由软件固定拼装：模型路径、随机 alias、127.0.0.1 和动态端口，以及 ctx-size/batch-size/ubatch-size=4096、parallel=1、n-gpu-layers=99、device=MTL0。
- 关联检查读取 --help 是为检查必要参数是否存在，不是解析完整参数并自动生成表单。
- 运行对话框只选择引擎和模型；尚无手动参数编辑。
- 当前引擎关联识别 llama.cpp 与 oMLX，Splash 尚未接入。Splash 的公开 serve CLI 与 llama.cpp 不同，需要自己的参数识别和运行适配。
- Splash 实际解析同时支持 --flag=value 与 --flag value；部分参数可重复并保留顺序，布尔开关靠出现表示 true，不能统一写成 --flag=false。值中的空格、等号及前导横线需要保真。证据：/Users/ghost233/code/Splash/server/serve_options.py:322、439、584。
- Splash 公开 --model 接收 HF OWNER/REPO[:VARIANT]，不接受本机 GGUF 路径；serve 子命令与内部服务的模型目录位置参数属于不同入口。证据：/Users/ghost233/code/Splash/install/launcher.py:404、468。
- Ghost Model Deck 当前启动采用 Process.start 的参数数组并关闭 shell 执行；通用参数编辑不能默默依赖 shell 展开变量、通配符等。
- oMLX 的真实模型池实现已存在，但当前 main.dart:109 未注入模型库，模型运行对话框仍调用只支持 llama provider 的入口，因此生产 GUI 尚未接通 oMLX 模型启动。oMLX 多个模型共享一个进程，进程级参数不能按模型各自同时生效；本次范围已按 Q21 A 收窄。证据：lib/omlx_engine.dart:1348、1446、1481；lib/model_run_dialog.dart:91。
