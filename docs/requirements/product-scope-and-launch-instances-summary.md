# 产品职责与实例管理：共同理解摘要

2026-10-12。Q1～Q19 及本摘要已由用户整体确认。跟踪 issue：[产品职责调整：多目录模型库、实例配置与委员会引用](https://github.com/Ghost233/GhostModelDeck/issues/82)。用户已调用 to-spec，正式规格按本摘要整理；本轮不执行实现或实际配置覆盖。

## 产品职责与界面

Ghost Model Deck 负责关联、设置和下载引擎，关联和下载模型，保存模型、引擎和参数组成的实例，并提供用户主动使用的聊天和题集测试。委员会成员引用保存的实例配置。

顶层保留“引擎”和“测试场”。实例管理拥有参数配置、保存、启动和停止职责，参数不再直接附着在模型上。模型库只展示识别出的模型及类型、维度、大小等信息，忽略“其他文件／其他目录”，不显示“待验证”或“待能力验证”。文件损坏、真实缺失和实际运行失败仍如实提示。

引擎显示真实仓库 `owner/repo`，本地关联显示实际地址，不使用“官方／标准／Local”等分类标志。默认来源沿用已确认的四项：ggml-org/llama.cpp 的 JEV b11381、llama.cpp 主线、incoai/splash 主线和 jundot/omlx 主线。保留 Git 地址克隆、构建和绑定能力，当前源码构建范围沿用已确认的 llama.cpp 及其分支。

引擎与模型下载集中在“下载”页面，显示进度和结果；长安装不锁住整个引擎设置或其他页面。

## 模型库与文件边界

模型库可以关联多个目录，新下载只写入一个保存目录。选择新的保存目录时自动加入模型库，但可以单独解除读取关联。解除关联保留文件与下载保存位置。

同一真实文件路径只展示一次；不同位置的文件副本分别管理，即使内容相同。读取已关联目录内链接明确指向的模型，按目标真实路径去重，不遍历未关联目标目录中的其他文件。从模型库删除这种链接项时，只删除库内链接，保留外部目标权重，继续遵守运行中的模型删除保护。

只要模型格式和基本信息能够识别，即可关联和创建实例。不以管理器预设的模型名称或架构名单限制选择；实际兼容性由引擎和用户实测判断。有明确依据的文件损坏或缺失仍提示。

## 实例与运行

实例配置保存名称、模型、具体引擎和完整启动参数快照。同一模型与引擎可以保存多份不同参数的实例。每份配置最多一个运行中的实例；重复启动复用启动作业或返回已有运行实例，需要多开时复制配置。

普通启动只核对进程健康、模型加载和实例身份，不自动做文本生成、嵌入或概率测试。实测由用户主动使用“测试运行”或测试场完成；健康或加载成功不表示模型成绩、准确率或所有接口能力已通过。

保存配置不启动或自动重启模型，只影响后续启动。已有进程和请求继续使用实际启动时的模型、引擎版本和参数。原位置的模型或引擎更新后继续引用该位置，重新读取当前文件与版本，下次启动使用更新后的文件；真实失效照实报告。

删除实例配置须先停止运行，只删除配置，不删除模型或引擎文件。失效实例可改选当前已有资源，保留实例身份、公开名及委员会引用，变更仍只影响后续启动。

## 参数编辑与短测试

参数直接显示为滚动列表，不使用展开入口或第二层编辑弹窗；窗口宽度自适应。修改显示 override，点击还原采用当前引擎默认值。实例保存后保持参数快照，后续引擎默认值变化不改变已有实例。

首次选择其他引擎时采用其默认参数，不自动转换旧 CLI。编辑期间切回原引擎可恢复原草稿，保存只保存当前组合；长期保留两种组合通过复制实例完成。

底部固定完整运行命令及取消、测试运行、保存。取消丢弃草稿；测试运行使用未保存参数建立临时实例，经普通公开 HTTP 发起短请求，结束后停止测试实例；原保存配置、已有运行实例和公开路由保持。保存只保存配置。

已确认的文本优先、未知参数保留、语法错误执行前修正和软件管理字段规则继续保留。

## 公开名称

HTTP 的 `model` 选择实例配置或委员会。实例显示名称与公开调用名分开，普通改名不自动改变公开名。默认公开名转小写，特殊字符归一为 `-`，新增重名采用 `-2`、`-3`，不使用 GUID／UUID 后缀。

实例和委员会共享唯一公开名称空间。创建委员会重名时先报错，再建议下一个可用名称，由用户确认后保存，不自动改名。

用户明确修改公开调用名后，旧名称失效，不保留别名；界面提示客户端更新。新名称冲突时先报错并给建议，不自动替换。

## 委员会与资源失效

委员会选择当前已有的实例配置。实例、模型、目录、磁盘或引擎等引用无法找到时，实例及引用它的委员会标红并说明原因，保留配置；恢复资源后恢复正常。仅未运行的实例显示“已保存”，不标红或显示“待验证”。

解除模型目录关联或磁盘离线不主动停止已有进程，在途及后续实际请求继续执行；引用失效期间禁止新的启动或重启，停止操作仍可用。真实进程失败如实记录。资源引用失效与进程是否仍运行分别表达。

删除实例配置后，委员会保留该引用并标红。原有“至少一个成员完整成功即可返回、明确报告 partial”的规则继续保留，不将部分成功描述为全体通过。

## 配置覆盖与验收

应用配置按新结构重新建立，不做旧配置迁移或旧格式兼容。仅覆盖应用配置，磁盘模型权重、引擎源码及编译产物、已有历史结果文件保留。

只编译和提供 macOS arm64。使用固定 Flutter／Dart SDK、原 lockfile、联网依赖解析和宿主机检查，不新建或恢复容器。

评测是用户可选功能，不要求每个模型运行全部题集。保留原生题目、固定 submodule、公开 HTTP／MCP、委员会对照、五项完整基准、Jevman 100 局和无快速试跑。UI 分批显示摘要，完整数据通过文件路径和 Finder 查看。

主线程推进，不启动子代理。同一作业只有一份；长作业执行 sleep 300 后收取，短检查直接收取。小修复先验证原失败及受影响模块，代码收齐后集中完成必要门禁；未受影响的成功证据复用，不无故重跑模型题集。未完成、取消、超时和缺证据不计通过。

当前草稿未完成开发或验收，既有应用产物和旧门禁不覆盖全部草稿。本摘要作为正式规格、实现和验收的已确认依据，不在本轮正式发布。
