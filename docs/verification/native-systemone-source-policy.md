# Git 源码引擎的原生 JEV 接入

2026-10-12，用户明确要求移除按具体模型 SHA、token 表和唯一源码 commit 授权的专用适配设计。Qwen、StartLux 是模型；运行引擎是 llama.cpp。用户选择本地 Git 仓库或 GitHub 地址及分支／标签／引用后，GMD 编译、登记并绑定该源码产物。

## 接入规则

源码构建表单保存“此仓库与版本声明支持原生 JEV 接口”的选项，对应 provenance 的 `supports_systemone`。声明支持时，已加载的 GGUF 文本／决策模型可配置为 JEV 来源，GMD 将请求直接转发到该实例的 `/v1/systemone`，不执行模型专用 token 标签、模板转换或概率计算，也不以启动探测决定是否接受该声明。

该能力的来源标记为 `source_declaration`。它表示仓库／版本的接口声明，不表示 GMD 已验证每个模型具有决策头、概率已校准或成绩良好。上游不支持具体模型、接口缺失或返回无效响应时，保留真实调用失败；不补概率、不改走文字答案、不悄悄替换其他引擎。文本服务和其他有效调用保持原生命周期。

Git 地址、请求 ref、实际解析的 commit、模型及产物摘要用于来源记录、完整性与复现，不是允许使用特定模型／commit 的白名单。保留文件完整性检查、实际实例身份、取消和失效隔离、预算、响应格式和候选完整性校验。声明关闭时不发布源码引擎的 JEV 能力。旧源码登记没有该字段时采用默认声明支持，后续重新构建可明确保存该选项。

llama.cpp v0.6.0 官方发布说明列出了 `/v1/systemone` 决策模型接口；这不保证普通 Qwen 模型也适用。具体行为由所选仓库／分支的引擎实现负责。来源：[官方 v0.6.0 发布说明](https://github.com/ggml-org/llama.cpp/releases/tag/v0.6.0)。
