## 问题陈述

现有 JevManager 围绕专用 JEV 决策模型工作。用户希望在这个基础上统一管理标准 LLM 和多种推理引擎，继续使用已有 Hugging Face 下载及独立模型库，并通过自己的 MacLauncher 管理服务。

目前模型资产、格式/量化、引擎安装、运行状态和客户端连接各有不同规则。下载成功或文件存在不能证明模型能在某个引擎中提供所需能力；逐个配置引擎地址、辨认是否真正就绪及确认退出后的资源归属增加使用成本。

用户需要一个完全接替旧应用的新项目，重新建立设置，复用模型文件，并为未来 OCR、图像和视频能力留下清楚的扩展边界。首期需要真实可运行的本机应用及可追溯验证，不以来源测试或模拟状态代替交付。

## 解决方案

提供 GhostModelDeck 标准 Flutter macOS 桌面应用，整合 HF 模型发现/完整包下载、独立模型库、引擎安装/版本管理、模型运行、JEV 委员会及 MCP。首期支持 llama.cpp 和 oMLX 的标准文本 LLM，同时保留已验证的 JEV 路径。

用户在模型库选择模型和具体引擎，显式启动后查看真实状态，再通过固定的本机 API 地址和稳定公开模型标识调用文本 Chat 或流式响应。应用负责受管实例的准入、请求和收尾，客户端请求不会隐式加载模型。

MacLauncher 通过一个整体推理服务启动接口及用户配置的启动模型集合，查询状态/日志或回收全部受管推理资源；应用保持独立运行和自身入口，支持从启动器打开窗口。

首期交付目标是当前目标 Mac 上的 Release 应用与真实功能/生命周期闭环。规划产物包括规范规格和具有验收条件、原生依赖的实现工单；代码实施、签名公证及更大范围评测分别按已确定阶段推进。

## 实现决策

### 产品边界与迁入

- 单用户、macOS / Apple Silicon 优先；首期只交付标准 LLM 与 JEV，引擎为 llama.cpp/oMLX。使用现成权重，零训练。
- 从已交付 JevManager 固定源码基线迁入生产代码、测试、原生工程、脚本、依赖锁定和开发资料；保留新项目历史、已有规范与用户未提交内容，逐项合并差异。
- 完全替代旧应用，个人设置重新建立；不迁移旧实例或个人配置，不要求双应用并存。
- 应用品牌为 GhostModelDeck，Dart package 为 ghost_model_deck，bundle 身份为 com.ghost233.ghostmodeldeck；双端原生 channel 为 com.ghost233.ghostmodeldeck/native，MCP 实现与新配置键为 ghostmodeldeck。
- 应用状态、下载暂存及安装收据使用新品牌独立命名空间；模型文件保持位置和所有权。JEV 能力名 consult_jev_council 和原协议保留。
- 采用紧凑导航、表格和直接操作，展示真实状态/错误与运行信息；保留发现、下载、模型库、引擎、委员会、API/MCP 信息及设置功能，无内置聊天或初始化工作台。

### 模块与共用入口

- 模型发现/包解析、下载与完整性、模型库、引擎安装、受管运行、委员会、协议适配和原生窗口各按职责组织。
- GUI、HTTP API、MCP 和 SDK 使用同一应用级业务控制及实际实例。各入口只负责输入/协议和呈现，不持有第二套模型、计算算法或资源管理逻辑。
- 模型资产、模型安装、引擎安装、引擎服务、推理实例、启动器服务、启动模型集合与公开模型标识分别表达；每种状态有一个权威来源。
- 外部数据在 I/O 边界校验为明确类型；并发、取消和晚到结果受生命周期归属约束。进程、连接、请求、订阅及暂存有明确创建者和释放入口。

### HF、模型包与模型库

- 搜索任意关键词/仓库，选择单个格式/量化变体；内部确定固定 revision、必要资产、大小、哈希和许可证元数据，不将逐文件勾选或全仓库所有精度当主流程。
- 覆盖单/分片 GGUF 与 MLX 的配置、权重、索引、tokenizer/template；进度、取消、恢复、校验、失败和冲突如实呈现。
- 保留 HF/代理来源功能，来源在任务创建时固定；下载完成和完整性验证分别表达。
- 本地扫描记录真实路径与文件身份，校验后建立新应用记录。扫描/下载不自动搬迁、重命名或覆盖已有正式模型。
- 显式删除只作用于用户所选范围并保留确认/在用保护；模型卸载或业务回收释放推理资源，不删除权重。

### 引擎、能力与就绪

- 应用提供受管安装与版本管理，也支持关联现有安装。安装记录包含精确版本、来源、摘要和环境；解除关联只移除登记，保留外部文件。
- llama.cpp 每模型独立受管进程，不使用 router；oMLX 为独立受管前台服务及原生模型池。单模型卸载和停止整个服务的作用范围分开。
- 普通 LLM 与 JEV 按具体资产、引擎版本和能力分别准入。标准 LLM 验证实际模型身份、加载状态和短文本调用；JEV 验证 typed 接口、题型及真实概率。
- 已发现、文件完整、兼容和能力 Ready 分开呈现。引擎安装、服务健康、原生模型列表、名称或格式后缀都不能单独证明可调用。
- oMLX 采用完整官方应用包的私有受管安装候选，保留运行器与随包 Python/框架资源布局，直接以前台服务模式运行，使用独立数据、模型目录、回环监听和端口；不启动全局 app/Homebrew 服务或修改系统 Python。
- 实际分发包必须通过摘要、布局、重定位、签名/启动校验和 Python/MLX/Metal 运行验证；构建源码不冒充发布包已运行通过，失败时阻断此安装声明。
- oMLX 核对目标身份和实际 loaded/is_loading/pinned。启用模型保持 pinned，关闭 model_fallback，固定物理模型 ID 与构造配置，禁止客户端触发 profile/alias/default 切换及重载。
- App 控制受管后端生命周期；每模型请求入场与停止协调，状态查询不能代替这种约束。运行代次改变撤销旧 Ready，内存拒绝/中止如实失败；pin 不等于内存预留。

### 本地 API 与运行交互

- 一个固定的 loopback Base URL，以稳定公开 model ID 路由到明确的受管运行组合；内部端口和原生名称不要求客户端重配，公开端口冲突明确失败。
- GET /v1/models 只列当前启用且 Ready 的标准 LLM，无模型时为空列表；POST /v1/chat/completions 提供文本非流式及 SSE。
- 请求、响应和 SSE 的公开 model 身份一致，保留真实文本、usage、finish reason 和结束/中断；客户端断开取消上游并释放许可。
- 模型由应用显式启动，客户端只复用 Ready 实例，不隐式启动进程、加载或换模型。未知、未就绪、无效及不支持请求明确拒绝，上游错误不补造成功。
- 首期输入为必填 model、文本 messages（system/user/assistant），可选 stream（默认 false）、max_tokens、temperature、top_p；类型、范围和两引擎响应需验证。其他字段明确拒绝，不透传管理接口、profile 或构造配置。
- 操作顺序为选择模型与具体引擎、显式启动、查看实际状态、复制连接信息；多个模型共享公开入口。
- 不宣称完整 OpenAI 规范或任意指定客户端全部接口兼容；JEV 概率能力与普通聊天 Ready 分开。

### JEV 与 MCP

- 保留两个或更多实际兼容席位，对相同上下文、题型及候选项并发咨询，返回每席原始结果/概率/选择、模型与引擎、耗时和故障。
- 成功席位按原等权规则综合并报告分歧/实际覆盖。非法、缺失或非归一化概率、失败席位及普通生成文本不参与综合。
- 覆盖 choice/score/noul、全/部分/单席/零成功、超时、取消和晚到结果；结构化与文本输出使用同一算法，不保证综合优于单模型或概率已校准。
- MCP 保留工具发现、校验和本机 HTTP，桌面和客户端共用委员会/实例；新实现身份使用 GhostModelDeck，连接客户端不重复创建模型。

### SDK 与窗口生命周期

- 采用固定官方 SDK；项目身份为 com.ghost233.ghostmodeldeck，名称 GhostModelDeck，单一 service 身份 inference，显示为推理服务。
- 使用 schemaVersion 1 项目关联配置和真实应用拉起入口，配置与 SDK 身份匹配，由用户显式关联；未连接启动器不影响独立使用。
- start 开启 LLM API/JEV MCP，并显式加载用户在新应用中选定的启动模型集合；不导入旧设置、替用户选择模型或下载权重，匹配实例复用且重复启动不创建副本。
- 命令确认只代表受理；加载中、空集合、缺资产和部分失败以真实状态报告。有接口但无可用模型不能宣称推理就绪。
- recycle 先关闭新入场，排空/取消 Chat、SSE 及委员会调用，再卸载当前全部受管模型、停止受管进程与 API/MCP；不限于启动集合。
- 回收保留应用、SDK 连接、启动配置和模型文件，可再次启动；下载任务仍由应用管理。GUI/SDK 共用业务控制，协议去重不代替业务幂等。
- onStatus 回报真实起停/就绪/故障及实际 UTC 观察时间；onLogs 回报真实批次，遵守限制、顺序、截断和未知原始时间/分流语义。
- 关窗继续后台，onOpenWindow 激活/重开主窗口；明确退出才完整收尾推理、下载和 SDK。失败保留残留与重试入口，不假报停止。
- 启动器退出/崩溃、断连/重连不回收业务或复制实例；连接生命周期独立于窗口/推理回收，第二连接冲突不抢占。
- 保留自身入口，不声明 onSetEntryManaged，不隐藏或交接入口；首期不依赖上游 SDK 缺失的失联自动归还。

## 测试决策

### 已由用户确认的测试边界

沿用前述规格及工程规范已经确定的边界：优先在一个最高层级的应用业务入口发起完整用例，经过 GUI、HTTP API、MCP、SDK 实际共用的业务控制。观察输入/输出、状态、文件与资源变化，不以入口内部的每个步骤建立新测试接缝。

可控替身仅用于 HF 网络、外部引擎进程/HTTP、SDK socket及原生窗口等 I/O 边界，复用现有边界；不访问私有方法、不逐行复刻算法、不增加测试专用业务入口或第二套模型管理。协议适配测试验证真实公开请求/响应，原生平台和真实模型另做联调。

并发、取消、晚到结果及资源释放使用可控调度/许可和可观察结果，避免以偶然时间或测试数量证明正确。状态、错误、原始输出和资源收尾都必须可被外部验证。

### 可借鉴的来源测试

- HF 浏览/固定 revision、模型包变体解析和下载器完整性、续传、冲突及暂存的公共行为测试。
- 模型库发现、完整性、格式/能力识别、删除和在用保护测试。
- 引擎登记/关联、模型起停、真实身份及 typed 准入、超时/取消/失败传播和生命周期测试。
- 委员会并发、有效概率、等权综合、并列/分歧、部分/零成功及晚到结果测试。
- MCP 工具发现/校验/文本与结构化一致及实际共用实例、窗口与退出相关的来源回归。

这些来自 JevManager 的测试和证据可迁入复用，但要在新身份和新业务边界下重跑；旧150项通过不计作 GhostModelDeck 通过。新 API、MLX/oMLX 与 SDK 控制须补充相应公开行为测试。
