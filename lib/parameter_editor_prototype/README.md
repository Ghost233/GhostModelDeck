# 参数编辑界面原型

这是用于比较界面结构的一次性代码，不属于正式应用。它要回答的问题是：如何让用户直接配置 llama.cpp 和自定义 Splash 的参数，同时看清修改的生效时机？

原型在浏览器中复现现有 Flutter 实例页的导航和列表背景。正式应用没有浏览器路由；预览服务把这个页面映射到 `/instances`，三个方案通过同一地址的 `variant` 查询参数切换。

## 运行

在仓库根目录执行一条命令：

```sh
python3 scripts/run-parameter-editor-prototype.py
```

默认打开 `http://127.0.0.1:8877/instances?variant=A`。可用 `--port` 选择预览端口，用 `--no-open` 只启动服务。按 Ctrl+C 关闭预览服务。

| 方案 | 地址参数 | 比较的问题 |
| --- | --- | --- |
| A：分组侧栏 | `variant=A` | 大量参数按组定位，右侧持续显示修改和生效状态 |
| B：右侧检查器 | `variant=B` | 在实例列表旁编辑，分组展开方式接近参考截图 |
| C：分步配置 | `variant=C` | 依次完成加载、生成、草稿和检查，减少一次面对的选项 |

底部悬浮栏或键盘左右箭头可以切换方案。输入控件内的方向键保留原有行为。三个方案共享内存中的编辑状态，刷新页面会恢复示例；URL 只保存所看方案、实例和引擎。

## 可以比较的操作

- 切换 Splash 与 llama.cpp，比较枚举、开关、数值、列表、路径和 Schema 编辑方式。
- 修改温度与生成长度，模拟保存后查看下一次请求，并用显式温度覆盖观察优先级。
- 切换草稿来源，查看旧 worktree 路径失效情境，再关闭草稿或明确选择来源。
- 选择 D3 决策示例，观察草稿不适用提示；选择 Qwen3.8 Splash 示例，观察必需草稿提示。
- 展开高级分组，直接编辑 ANE、磁盘缓存、compact、线程和 KV 格式等参数。
- 查看各方案的全部原型状态，比较保存前、保存后及模拟重启后的区别。

窄窗口中可点击“状态与生效”，打开同一份修改清单、请求模拟和完整状态预览。

模型和资源都是展示用数据。Splash 目录复用已知本地路径字符串，llama.cpp 草稿使用明确标注的虚构 GGUF 资源。选择器和检查均为模拟，不扫描文件、不计算权重、不调用推理，也不写入正式配置。密钥输入不会保存或发送，状态预览隐藏其示例值。

本轮只核对原型能运行及上述交互，不新增测试或运行生产测试、性能测试。原生兼容性与真实模型验证属于后续生产实现。

运行检查：Python AST 语法检查、提取的内联脚本 `node --check` 和 `git diff --check` 均退出 0。实际浏览器操作已核对方案切换保留温度修改、输入框方向键不切换方案、草稿选择、旧路径错误、关闭草稿、必需草稿提示，以及保存温度 0.6 后的请求默认值和单次覆盖 0.4。

预览截图保存在本地 `.tooling/parameter-editor-prototype/variant-a.png`、`variant-b.png` 和 `variant-c.png`，用于此次比较。

## 结论与留存

2026-10-20，用户明确选择 A：分组侧栏。所回答的问题是如何组织大量类型化参数，并同时表达生效时机和实际运行状态。用户未另行说明选择原因。正式实现采用 Flutter 原生控件，沿用已确认的参数、资源和生效规则；B、C 保留为比较依据。完整原型按 prototype 技能留存在独立的一次性分支，实现工单关联该分支。
